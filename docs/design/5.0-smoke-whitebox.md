# 5.0 smoke suite: white-box inventory

The smoke suite (`test/sections/*.sh`) is being rewritten (#46, A2) to call only `$HV_BIN <group> <verb>`. An item is white-box when the test imports `hvlib*`, sources a `bin/*.sh` file, greps helper source or skill prose for helper names, asserts the `bin/` layout or file modes, asserts stderr that names an old helper, or calls a helper the triage deletes. Plain helper calls and `.hv/bin` mirror calls are not listed: they convert by name to the verb in `docs/design/5.0-helper-triage.md`.

Line numbers are per section file. Verb names follow `docs/design/5.0-verb-contract.md`. A converted test asserts exit codes and `--json` data fields, not message text (rule 8).

## Marker format

Every white-box assertion in `test/sections/*.sh` sits inside an explicit block. One form only; the
guard (`test/sections/72_whitebox_guard.sh`, scanner `test/whitebox-scan.awk`) parses it.

```
# white-box-begin: go-unit A5 #49     goes away with the A5 Go unit test
# white-box-begin: A9 #53 keep        goes away when A9 deletes bin/ and the mirror
# white-box-begin: A9 #53 doclint     prose lint; moves to a docs-lint script at A9
...
# white-box-end
```

- The tag is exact. `go-unit` takes the phase and its issue: A3 #47, A4 #48, A5 #49, A6 #50, A7 #51, A8 #52. The A9 tags are `A9 #53 keep` and `A9 #53 doclint`.
- Blocks do not nest and close before the file ends. A whole-file section opens the block after the shebang and closes it on the last line.
- A block covers the whole assertion, its fixture setup and its `pass`. When two proposals meet in one stretch, split the block; do not widen one.
- The guard fails on any line outside a block that uses `$BIN` (or assigns or exports `BIN`), an `hvlib` import, `.hv/bin`, `$REPO/bin` (also `"$REPO"/bin`), a `bin/hv-` path, `bin/*`, `install_helpers`, `SKILL.md`, `$REPO/hv-*`, `$REPO/references`, `$REPO/docs`, a `PYTHONPATH=` override, `git ls-files`/`ls-tree`, or an assignment of `$REPO` to another variable (variable indirection). `HV_INSTALL_ROOT="$REPO"` and `$REPO/.claude-plugin` are allowed. Comment lines are exempt. It also rejects a malformed or retired marker (`# white-box:`), a bad tag, a nested or unclosed block. Fixture text must not contain these strings either: write `scripts/x` rather than `bin/hv-x`.
- The porter who adds the Go test deletes the block, markers included, in the same PR. A9 deletes every `A9 #53 keep` block and moves every `doclint` block into the docs-lint script.
- Resolved in #173: the skill and doc prose greps now live as `PROSE_RULES` in `test/validate-skills.py` (section 32 is gone, the other `doclint` blocks were deleted). F29 became smoke section 79 (a dangling `--repo`/`--repos` exits 2 and leaves state untouched). F30 needs no replacement: walk-up from a sub-directory is pinned by sections 15, 16 and 18. The two `doclint` blocks left in section 70 test the validator and `migrate v4` themselves, not skill prose.

## Proposals

| Proposal | Meaning |
|---|---|
| `verb <name>` | Convert to that verb call. |
| `go-unit Ax` | Moves to Go unit tests in phase Ax of the triage. Until that Go test lands, the assertion stays in the section, wrapped in a `white-box-begin: go-unit Ax #N` block (see Marker format); the porter deletes it with the PR that adds the Go test, so no coverage is moved before its new home exists. |
| `keep-marked` | Stays white-box until A9 deletes `bin/`. The section wraps it in a `white-box-begin: A9 #53 keep` block. Skill-prose and doc greps are tagged `[doclint]` (block tag `A9 #53 doclint`): they outlive A9 and belong in a docs-lint script. |
| `drop` | The subject is a helper the triage deletes. The 5.0 replacement is named where one exists. Behaviour that still ships until A9 (the `.hv/bin` mirror, `hvlib` re-exports) is `keep-marked`, not `drop`, so the port never runs without coverage. |

A row that has two halves with different proposals is split into two rows.
