## E: Codex workers

E1 (#68) runs OpenAI's Codex CLI as a round or pool worker beside Claude Code. It adds no verb: `worker dispatch` and `round assign` take `--kind codex`, `doctor` gains a `codex` check. A codex worker is a visible TUI session in a herdr tab, like a claude one; headless `codex exec` stays out (#44).

- **Kind.** `--kind` picks the harness; the default is the slot's recorded `kind`, else `claude`. `assign` records it on the slot (C9) and passes it to dispatch. The kind selects the launch command, and under herdr the command's binary must match the kind (`claude` or `codex`, by basename after any leading `KEY=VALUE` tokens), so `herdr agent start --kind` is derived from the command, never assumed.
- **Launch command.** New key `work.codexCommand`, a silent default (not seeded by init): `codex --model {model} --dangerously-bypass-approvals-and-sandbox --dangerously-bypass-hook-trust --no-daemon --no-alt-screen`. `{model}` takes the tier's model, as in `work.workerCommand` (C9); with no model chosen (a bare `worker dispatch`, or `round assign` with `round.tiers.codex` unset) the default drops `--model {model}` and Codex uses its own default, while a custom command that still holds `{model}` exits 2. The bypass flag is the codex twin of `--dangerously-skip-permissions`, for the same reason (nobody answers prompts in a worker pane; scope, not gating, bounds it). `--no-daemon` keeps the session in the pane's own process tree: a session hosted by Codex's background app-server would outlive `tab close`, and dispatch's kill must be provable. `--no-alt-screen` keeps the pane's scrollback readable: herdr refuses `agent read --source recent-unwrapped` while a Codex agent in the alternate screen is working, which would leave `worker poll` blind mid-turn (seen live, #70 spike). `--dangerously-bypass-hook-trust` is there because Codex opens a hook-review screen on the first prompt for any untrusted hook, including herdr's own integration hook in every slot home; the screen swallows the prompt and herdr reports `idle` or `working`, never `blocked`, so no dialog handler sees it (seen live, #70 spike). The worker already bypasses the sandbox and approvals, so trusting hooks unread adds little; the Claude-worker parity is `--dangerously-skip-permissions` (maintainer ruling, round 4). The resume guard also refuses codex's `resume` and `fork` subcommands.
- **Codex home.** A codex slot runs on the default Codex account, as a claude slot runs on the configured accounts or the default config dir: rota sets no `CODEX_HOME`, so Codex uses `~/.codex` (or the `$CODEX_HOME` of the environment) and its login (maintainer ruling, round 5, #358). The slot's own worktree is the separation; several Codex processes sharing one home is normal Codex use, and sessions and history land in it. rota writes nothing to that home's `config.toml` or `auth.json`. A slot gets a state directory of its own at `<git-common-dir>/rota/codex/<slot>` (0700, created on the first codex dispatch, never deleted) that holds only the prompt key: beside the round lease, outside the worktree (it would dirty `git status`), outside `.worktrees/` (so `reap` never sees it). Per-slot homes that earlier releases made in the same place are left as they are; rota stops pointing Codex at them, and their key files keep working because the key path is the same.
- **Codex accounts.** `work.codexAccounts` (silent default `[]`) lists `{name, codexHome}`, the counterpart of `work.accounts`. Empty: the default home. Configured: a slot keeps the account in its `codexAccount` field while that name is still configured, else takes the account with the fewest other codex slots (ties in config order, nameless entries skipped); `dispatch` records it on the slot and passes its `codexHome` as the tab's `CODEX_HOME`. `assign` and `dispatch` pick the same way, so the preflight checks the home the worker will use. There is no Codex usage meter, so the pick balances slot counts, not headroom. A per-slot home is used only if it is configured as an account.
- **Seeding.** Nothing is seeded into a home. Folder trust and the update check ride on the launch line, right after the binary, ahead of the prompt-check hook: `-c 'projects."<worktree>".trust_level="trusted"' -c check_for_update_on_startup=false`, so neither dialog opens in an unattended pane and no `config.toml` is written. Under herdr, when `herdr integration status` (with `CODEX_HOME` set only for a configured account) does not report codex `current` in the home Codex uses, rota runs `herdr integration install codex` there, once: the codex counterpart of the claude integration the `hook` check asks for. rota never writes `auth.json` and never copies one.
- **Login.** rota does not log in. Before anything is marked, `assign` and `dispatch` run `codex login status` against the home the slot will use (`CODEX_HOME` set only for a configured account); a non-zero exit is exit 5 with the hint `codex login` for the default home, `CODEX_HOME=<home> codex login` for an account. Copying an `auth.json` between homes is not a shortcut: a ChatGPT login carries a rotating refresh token, so two copies refresh independently and can invalidate each other.
- **Capability, not version.** rota pins no Codex version (maintainer rule: no version numbers for Codex or Claude). Before anything is marked, `assign` and `dispatch` run `codex --version` under the home the slot uses (`CODEX_HOME` set only for a configured account), which only proves codex is installed and runnable (else exit 5), then `codex --help`. Every long flag of the resolved launch line (`work.codexCommand`, else the default) must appear there as a whole word, else exit 4, `blockedBy: "codex flags"`, naming each missing flag. A custom command is probed for its own flags only. `--accept-codex-version` is a deprecated no-op that prints a one-line warning, so existing scripts keep working. `doctor` shows the version when `codex --version` prints one and fails only when it cannot run.
- **Host.** herdr only: `tab create` passes `--env CODEX_HOME=<home>` only for a configured Codex account (the account is fixed at tab creation, as `CLAUDE_CONFIG_DIR` is) and `agent start --kind codex`. `work.accounts` and its usage meter are Anthropic's and are skipped for a codex slot; `work.codexAccounts` spreads slots but has no meter. Under tmux a codex dispatch exits 5 (`codex workers need work.dispatch=herdr`): the tmux host detects a booted session from Claude Code's screen text and has no codex equivalent.
- **Startup dialogs.** herdr reports Codex's folder-trust, update and hook-review screens as `idle` or `working`, never `blocked`, so the herdr dialog handler (`agent_not_ready` at start) cannot see them. They are prevented instead: the `-c` flags on the launch line cover folder trust and the update check, and `--dangerously-bypass-hook-trust` covers hooks. The texts are recorded in the #70 spike.
- **Prompt check (#3).** Signing is mechanical for codex, not left to the model. Each codex task dispatch writes a fresh 32-byte key, hex, to `<git-common-dir>/rota/codex/<slot>/rota-prompt.key` (0600, atomic), and `dispatch` records `kind` on the slot so a relay knows to sign. Every brief and relay to a codex slot ends with `--- ROTA-SIG <hex> ---`, the HMAC-SHA256 under that key of the payload (ORCHESTRATOR header included) with every Unicode space removed: herdr and the Codex composer may rewrap or trim whitespace, never content. The launch line gets `-c features.hooks=true -c hooks.UserPromptSubmit=[...]` right after the binary, a hook running `<rota> worker prompt-check --key <file>` (`<rota>` is the dispatching binary's absolute path) inside a shell wrapper that turns any non-zero exit into 2, adding a reason on stderr when the check's own exit was not 2. The hook passes a prompt whose first non-blank line is the ORCHESTRATOR header and whose last is a matching `ROTA-SIG`, or one starting `m:` (maintainer ruling: the typed-answer channel stays, a known residual path). Everything else exits 2 and Codex drops it before the model. Two fail-open paths are closed: Codex skips hooks without `--dangerously-bypass-hook-trust`, so dispatch refuses a codex launch without it (exit 5, before anything is killed); and a hook that errors with another code does not block, hence the wrapper. A relay to a codex slot with no key file exits 5. Verified by hand on codex-cli 0.159.2 (rota no longer gates on the version) (`-c` hook layer, exit-2 block before the model, no hook run without the trust flag). Threat boundary: the key is not secret from the worker or from other processes of the same user (it is a 0600 file the worker can read), so this check stops text typed or pasted into the pane, not a local process that can read the key. Codex behaviour when the hook hits its 30s timeout is unknown. Because the version is not gated, a Codex that ignores `-c features.hooks=true` is not detected. Claude workers are unchanged: no key, no trailer.
- **Classification.** Unchanged code: herdr reports the codex agent's state natively, and `worker poll` and `round wait` apply the same sentinels (`ROTA-DONE`, `ROTA-BLOCKED`) on top. `limited` gains Codex's usage-limit text once recorded live. The working, idle and blocked check on the Codex TUI is manual and recorded in the PR (#68).
- **`rota doctor` `codex` check.** Placed after `hook`. `skip` when codex is not on PATH and no `work.codexAccounts` are configured. Otherwise `fail` when codex is missing (accounts are configured), `codex --version` cannot run (hint: install codex-cli), or a configured account's home is not logged in (hint `CODEX_HOME=<home> codex login`) or, under herdr, lacks the integration (hint `CODEX_HOME=<home> herdr integration install codex`). `detail` names the version (when printed) and the homes checked, and on a pass with `round.tiers.codex` unset notes that the tiers are optional (workers use Codex's default model, #68). `codex --version` runs with `CODEX_HOME` set to a slot home when one exists, so the check never needs `~/.codex`. With no accounts it checks the default home and only notes a missing login or integration on a `pass`, since a project that never runs codex workers has no reason to log in.
- **Not in E1.** Codex subagents and solo mode (E3, #70, then C8), a Codex usage meter, codex under tmux, a second-opinion runner (#158 retired it).

### D1: statusline dump, Stop hook and handoff

D1 (#65) lets a long-running Claude orchestrator hand off and exit before its context or usage runs out. Three small pieces: a **state dump** fed by the statusline, a **Stop hook** that blocks above a context threshold, and a **SessionStart hook** that injects the handoff into the next session. It acts only on the orchestrator. Restarting the pane after the exit is D2 (#66), and what to do about a usage limit is D3 (#67); D1 writes the state they read and starts nothing.

Status: **ratified by the maintainer, round 4** (AskUserQuestion, relayed by the orchestrator). Statusline: "Wrapper", so `--wrap-statusline`, record the original, uninstall restores it exactly, and `dump` swallows its own errors. Hook scope: "Project-local", `.claude/settings.local.json`. Handoff file: `.rota/handoff/<base>.md`, delivered by the SessionStart hook. The 75% threshold default is ratified as configurable. The context fallback from `current_usage` and `context_window_size` is accepted; `used_percentage` stays unverified. If a plugin cannot register a `statusLine`, the wrapper does not need it to. Still my own calls, unratified: the verb names (`rota hook install`, not `rota statusline install`, since one command installs the hooks and the statusline together), the three other config defaults, the loop-prevention counts and the lease-based orchestrator test.

- **The session state file.** `<git-common-dir>/rota/session/<session_id>.json`, written atomically (`fsio`) on every statusline refresh. It sits next to the round lease for the same reason: per repo, shared by every worktree, never tracked, and no new `.rota/.gitignore` entry. Fields: `sessionId`, `cwd`, `updatedAt` (RFC 3339), `contextPct` (number or absent), `rateLimits` (the statusline's `rate_limits` object verbatim, absent when the session has none), and `raw` (the whole input JSON, so D3 and later phases read fields D1 did not anticipate). `contextPct` is `context_window.used_percentage` when present; otherwise it is derived from `context_window.current_usage` (input, cache-creation and cache-read tokens) over `context_window.context_window_size`; absent when neither exists. Files for a session untouched for 24 h are removed by the next dump.
- **"The orchestrator."** The session whose Claude process holds the round lease (`internal/roundlease`, C3), matched with `Holder.SameAs` on the nearest non-shell ancestor, as `rota round start` records it. No lease, or a lease held by another process, means the hook is a no-op and exits 0 with no output. This is how the plugin or settings registration can be wide without touching workers, which also run Claude but never hold the lease. The dump itself is written for every session, because the statusline cannot know which it is.

### rota statusline dump
rota statusline dump [--then <command>]
repo: none
data: none. Prints nothing of its own; the verb is a statusline command, not a query.
exit: always 0. A statusline that fails blanks the user's bar, so every error (unreadable stdin, no git dir, unwritable state directory) is swallowed and goes to stderr only when `ROTA_STATUSLINE_DEBUG` is set.
old: none (new in D1)
note: reads the session JSON from stdin, writes the state file, then runs `--then` (through `sh -c`) with the same bytes on stdin and the real stdout and stderr, and returns after it. Without `--then` it prints nothing, which leaves an empty statusline; `rota hook install` never installs that form over an existing statusline (see below). The dump runs first and its failure never skips the command. `--then` exiting non-zero still exits 0, with the command's stdout passed through unchanged.
note: no global `--json`: stdout belongs to the wrapped command. The verb rejects `--json` (exit 2).
env: `ROTA_TEST_NOW=<rfc3339>` fixes `updatedAt` and the 24 h expiry. Not part of the CLI.

### rota hook stop
rota hook stop
repo: none
data: none. The verb speaks Claude Code's hook protocol: JSON on stdout, exit 0.
exit: always 0, including on a state it cannot read: a broken hook must never wedge the orchestrator in a block loop.
old: none (new in D1)
note: reads the Stop payload on stdin (`session_id`, `stop_hook_active`, `cwd`). Passes (no output) unless all hold: this session is the orchestrator; its state file exists and its `updatedAt` is no older than `orchestrator.stateMaxAgeSeconds` (a stale reading is not acted on); `contextPct` is at or above `orchestrator.handoffThreshold`; and no fresh handoff exists yet. Otherwise prints `{"decision":"block","reason":"…"}` where the reason names the percentage and the threshold and tells the orchestrator to write the handoff to the handoff path below, commit nothing it does not own, and run `/exit`.
note: loop prevention. When the payload carries `stop_hook_active` true and the handoff file now exists and is newer than the block, the hook passes: the orchestrator did what it was told and is exiting. When `stop_hook_active` is true and no handoff exists, the hook blocks once more, at most `orchestrator.handoffMaxBlocks` times per session (default 2, counted in the state file), then passes and records `handoffFailed: true` in the state file so D2's breaker reads it. A session that cannot write a handoff must not be held forever.
env: `ROTA_TEST_NOW=<rfc3339>` fixes the clock; `ROTA_TEST_HOLDER_PID=<pid>` stands in for the nearest non-shell ancestor in the lease test (also on `session-start`). Not part of the CLI.
note: (#81) a second rule, independent of the state file: when this session is the orchestrator, the round host is not solo, a slot is not `idle` (or an escalation is pending) and no `rota round watch` is running (`round-watch.json` names a live process), the hook blocks with a reason that tells the orchestrator to start `rota round watch` in the background and lists the slots already waiting on it. It runs after the handoff rule, so a handoff block wins, and it works without a statusline state file. A payload with `stop_hook_active` true passes, so a refused watch never loops: one reminder per stop.
note: the percentage is read from the state file, not the payload, because the Stop payload carries no context figure (Claude Code hooks reference, checked in round 4). The reading is one statusline refresh old at worst.

rota hook prompt
repo: none
data: none (hook protocol: JSON with `hookSpecificOutput.additionalContext`, exit 0)
exit: always 0.
old: none (new in #81)
note: the UserPromptSubmit hook. When this session is the orchestrator and some slot is not `idle` or an escalation is pending, it injects a one-line digest as `additionalContext` on every maintainer message, read from the registry alone (no host or forge call): `rota round 1: ben busy #81; dana done https://…/pull/7 (needs you); 1 escalation(s) pending. ### rota hook session-start
rota hook session-start
repo: none
data: none (hook protocol: JSON with `hookSpecificOutput.additionalContext`, exit 0)
exit: always 0.
old: none (new in D1)
note: acts when `source` is `startup` or `clear`, this session holds the round lease, and the handoff file exists. It prints the handoff body as `additionalContext`, prefixed `Handoff from the previous orchestrator session, now consumed:`, then deletes the file. `resume`, `compact` and `fork` keep the file: the session already has its context. Consume-on-inject means a crash between the print and the model reading it loses the handoff; the verb therefore moves the file to `<handoff path>.consumed` instead of deleting it, and the next write of a handoff replaces that. A read failure leaves the file and prints nothing.
note: lease timing. `rota round start` takes the lease; a fresh session that has not run it yet holds nothing, so the hook passes and the file waits. D2 restarts the orchestrator with the lease still free, so the restarted session's first act is `rota round start`; the orchestrate skill (C7, #63) says so and says to read the handoff then. The hook also injects when no live lease exists (none, or a stale one whose holder is gone, which is what an exited orchestrator leaves) and the handoff is younger than `orchestrator.handoffMaxAgeSeconds` and was written by a Stop-hook block (it carries the marker below), so an orchestrator restarted before it reclaims the lease still gets it.

#### The handoff file
`.rota/handoff/<base>.md`, the path `rota status handoff <base> --canonical` already returns (base is `git.base`, `main` here). The file carries first line `<!-- rota-handoff: orchestrator -->` and `<!-- written YYYY-MM-DDTHH:MM:SSZ -->`; the body follows `references/handoff-template.md`, with a `## Round state` section the orchestrator adds (slots, who holds what, merges pending, escalations open). `/rota-pause` already writes this file for a session on the base branch, so the user's manual pause and the forced one are the same artefact, and `/rota-work` (no argument) consumes either. "Fresh" is `updatedAt` within `orchestrator.handoffMaxAgeSeconds` (default 900). D2 reads the same path and the same freshness rule; D1 owns the definition.

### rota hook install
rota hook install [--scope <project-local|project|user>] [--wrap-statusline]
repo: none
data: {"scope": string, "settingsPath": string, "hooks": []string, "statusline": "installed" | "wrapped" | "kept" | "present", "changed": bool}
exit: 4 when a plain install would replace or shadow a statusline, that is one already in the chosen file or in a lower-precedence scope, and `--wrap-statusline` is not given (`blockedBy`: `statusline exists`, `changed` false, nothing written); 3 when a project scope (`project-local` included) is asked outside a project root; 70 when the chosen settings file does not parse (rota never overwrites it)
old: none (new in D1)
note: merges into the chosen settings file and never replaces anything it did not write. It adds a `Stop` hook running `rota hook stop`, a `SessionStart` hook running `rota hook session-start` (matcher `^(startup|clear)$`), a `UserPromptSubmit` hook running `rota hook prompt` (#81), and a `statusLine` of `rota statusline dump`. The hooks carry a marker in their command (`# rota-hook`) so a re-run finds and updates them instead of stacking duplicates; re-running with nothing to change is `changed: false`.
note: **statusline coexistence.** If any scope already sets a statusLine, plain `install` refuses (exit 4). With `--wrap-statusline` it rewrites the effective one to `rota statusline dump --then '<original command>'` in the scope being written, and records the original beside the entry (`"rotaWrapped": "<original>"`) so `uninstall` restores it exactly. When the original came from another scope's file, the new entry also carries `"rotaWrappedFrom": "<scope>"` and `uninstall` deletes the entry instead of restoring a copy. The settings file is rewritten in the `internal/jsonx` form (two-space indent, key order kept, non-ASCII as `\uXXXX`), so a file in that form round-trips byte for byte; another layout is normalised on the first write. The original is read from the highest-precedence scope that sets one (project-local, then project, then user), and written to the chosen scope: wrapping a user-level statusline from `project-local` leaves the user file untouched and shadows it only inside this repo. `statusline` in `data` says which happened: `installed` (none before), `wrapped`, `kept` (a rota-wrapped one was already there), `present` (a statusline in a higher-precedence scope than the chosen file, or a rota one in another scope, already wins; the hooks still install and the statusline is left alone).
note: default scope is `project-local`, `.claude/settings.local.json` in the project root, which Claude Code treats as per-developer and does not commit. Only one scope per call.

#### Config
Four keys, all silent defaults (not seeded by init), under `orchestrator`: `handoffThreshold` (integer percent, 1 to 100, default **75**), `stateMaxAgeSeconds` (default 120), `handoffMaxAgeSeconds` (default 900), `handoffMaxBlocks` (default 2). Documented in the five places the project rules name, and read through one `internal/` accessor so the hooks and doctor agree; an out-of-range value exits 70 for every verb that reads it, and the hooks treat it as a pass, never a block.

#### Doctor
Two checks, appended after `hook` (the existing `hook` check is herdr's agent integration and keeps its name): `statusline` (the effective statusLine, read through Claude Code's precedence, runs `rota statusline dump`, directly or through `--then`; `fail` with the hint `rota hook install --wrap-statusline`) and `stop-hook` (a Stop and a SessionStart entry marked `# rota-hook` exist at some scope and the command's first word resolves on `PATH` (the plugin's `bin/rota` launcher is not the running binary, so equality is not tested); `fail` with the hint `rota hook install`). **Opt-in (gate 16, round 4).** The hooks are opt-in, so doctor must not fail every project that has not installed them. Both checks `skip` outside a rota project and unless something `rota hook install` writes is present in a settings file in scope: a `# rota-hook` entry for any event, or a statusLine that runs `rota statusline dump` (directly or wrapped). The skip detail is `hooks not installed (opt-in)` plus the hint `rota hook install`, and names any settings file it could not read. Once opted in, both fail on a broken or partial install: a missing Stop or SessionStart entry, a command that does not resolve, a statusLine that does not run the dump, or an unreadable settings file. A user's own statusLine or unmarked hooks never opt in. `orchestrator.*` keys are not a signal: setting a threshold is not installing hooks. Both are read-only, `pass`/`fail`/`skip` as the other checks, and both look at every account's `configDir` settings plus the project's, since the maintainer runs `.claude-personal` and `.claude-work`.

#### Tests (acceptance → check)
- State file updates on each refresh: smoke section 90 feeds three JSON payloads through `dump` and reads `updatedAt` and `contextPct` change; a payload without `used_percentage` derives it from `current_usage`.
- Above the threshold the Stop hook blocks, below it passes: section 91 with a fixture lease holder, at 74, 75 and 99; no lease passes at 99.
- Loop prevention: `stop_hook_active` with and without a handoff, and the `handoffMaxBlocks` cap.
- Fresh session receives and consumes the handoff: `session-start` on `startup` injects and renames; on `resume` it keeps the file.
- Install and uninstall round-trip: a fixture settings file with an existing statusline is wrapped and restored byte for byte; a re-run changes nothing.
- Doctor: the two checks against fixture settings, missing, wrapped and current.
- The Go gate for `internal/hook` (new), `internal/doctor`, `internal/roundlease` readers and `cmd/rota`; frozen scenarios for the five verbs.

#### Rulings and what is still mine
Ratified (round 4): the wrapper for statusline coexistence, `project-local` as the install scope, `.rota/handoff/<base>.md` as the handoff file with SessionStart delivery, 75 as a configurable default threshold, and the `current_usage` fallback. Unverified and noted for the PR: `context_window.used_percentage`; `rate_limits.five_hour|seven_day.{used_percentage,resets_at}` are confirmed in use by the maintainer's own statusline script. The wrapper's cost is that the user's script runs as a child of `rota` on every refresh, which is why `dump` swallows every error. A root `HANDOFF.md` was rejected because it would dirty the base checkout that `rota round wind-down` requires clean; with the hooks uninstalled a restarted orchestrator reads nothing and `/hv-next` is the manual route.

My own calls, unratified: verb names; `stateMaxAgeSeconds` 120, `handoffMaxAgeSeconds` 900 and `handoffMaxBlocks` 2; that "orchestrator" means the lease holder; and shipping D1 without waiting for #63, whose only link is one line in the orchestrate skill (PR #194) telling a restarted orchestrator to run `rota round start` and read the handoff.

Not in D1: restarting the pane (D2), limit handling (D3), a non-Claude orchestrator, and any change to how `/rota-pause` writes.

### D2: keepalive supervisor

D2 (#66) restarts the orchestrator in the same pane after it exits, but only when it left a fresh handoff (D1). It stacks on D1: the handoff path, its freshness rule and the SessionStart injection are D1's, unchanged.

Status: **ratified by the maintainer, round 4** (AskUserQuestion, relayed by the orchestrator; answers in `.worktrees/finn-q.md`). The supervisor holds the lease via `ROTA_ROUND_HOLDER_PID`, with the small C3 edits (`roundlease.Discover`, `round start` numbering) and tests. The supervisor shape, `rota keepalive run -- claude …`, departs from the issue's wording and is ratified as such. `orchestrator.escalateIssue` is unset by default and this repo sets nothing for now: the breaker's notification is a host notification only. The restart prompt is appended as the last argument, with the default text below. Still my own calls, unratified: the defaults 10, 3 and 5 s, progress by handoff SHA, and the state file's shape.

- **A supervisor, not a watcher.** `rota keepalive run -- <command…>` is the pane's foreground process and runs the orchestrator (`claude …`) as its child. It gets the child's real exit status from `wait`, so it needs neither herdr's process-info PID nor `agent_status_changed`, works the same under tmux, and "the same pane" is simply the pane it already owns. The issue's "watch for the process to exit" is satisfied by being its parent.
- **The lock is the round lease.** No second lock. `run` takes the C3 lease (`internal/roundlease`) as the holder, with its own PID and start time (and the pane from the environment, as `Discover` reads it), and holds it for its whole lifetime, across restarts. It sets `ROTA_ROUND_HOLDER_PID=<its pid>` in the child's environment, and `roundlease.Discover` returns that PID as the holder whenever the variable is set and no explicit `--holder-pid` was given. So every `rota round start`, `wind-down` and D1 hook the orchestrator runs sees the supervisor as the lease holder and treats the session as the orchestrator, without any change to `Holder.SameAs`. Consequences: a second `run`, or a second orchestrator started by hand while the supervisor lives, is refused by the lease it already enforces; the round number survives a restart, because `rota round start` in the restarted session renews the lease instead of reclaiming a stale one; and D1's SessionStart hook injects the handoff immediately, with no `rota round start` first (this removes the lease-timing caveat of D1's `session-start`).
- **Round numbering.** `run` takes the lease unnumbered (`round` 0). The first `rota round start` under it numbers it (registry `round` plus one, written to the lease and the registry); a renewal under the same holder keeps the number. A lease the supervisor finds already numbered, with itself as holder, is reused.
- **State.** `<git-common-dir>/rota/keepalive.json`, next to the lease, rewritten under its own `fsio` lock on every transition: `{"pid": number, "startedAt": string, "command": []string, "status": "running" | "stopped", "restarts": number, "noProgress": number, "runStartedAt": string, "lastHandoffSha"?: string, "lastExit"?: {"code": number, "signal"?: string, "at": string}, "stopReason"?: string, "escalation"?: string}`. D3 does not write here: its usage-limit log is `limits` in `.rota/workers.json`, the round state (see D3), so this file stays the supervisor's own.

### rota keepalive run
rota keepalive run [--max-restarts <n>] [--breaker <n>] [--backoff <seconds>] [--prompt <text>] [--first-prompt <text>] [--config-dir <dir>] [--no-limits] -- <command> [<arg>…]
repo: none
data: {"stopReason": "no-handoff" | "interrupted" | "max-restarts" | "breaker", "restarts": number, "noProgress": number, "lastExit": {"code": number, "signal"?: string}, "escalation"?: string, "changed": bool}
exit: 0 when it stopped because the orchestrator exited without a fresh handoff or the supervisor was interrupted (`no-handoff`, `interrupted`); 1 when it stopped on `max-restarts` or `breaker` (same `data`); 2 when `<command>` is missing, a number flag is invalid, or `--` is absent; 70 when a `limits.*` key is out of range (not checked with `--no-limits`); 3 when there is no project root; 4 when the lease is held by another live or foreign holder (`blockedBy`: `lease held`, `changed` false, nothing started); 5 when the command cannot be executed or `git` fails (the lease is released and the state file records `stopReason` `spawn-failed`, a value `data.stopReason` never has)
old: none (new in D2)
note: not a query. It blocks for the life of the orchestrator and its restarts, so `--json` prints one envelope at the very end; the child owns the terminal until then. Flags override config for this run: `--max-restarts` `orchestrator.keepaliveMaxRestarts`, `--breaker` `orchestrator.keepaliveBreaker`, `--backoff` `orchestrator.keepaliveBackoffSeconds`, `--prompt` `orchestrator.restartPrompt`. `--no-limits` (D3) does not run the usage-limit watcher beside the command; it is a flag, not a key.
note: loop. (1) Refuse unless the lease is free, stale or this supervisor's. Take it. (2) Start the command with the current directory, stdio and process group unchanged, plus `ROTA_ROUND_HOLDER_PID`. (3) On the child's exit, record `lastExit` and decide from the handoff file (`.rota/handoff/<base>.md`, D1): **fresh** is D1's rule (it exists and its mtime is within `orchestrator.handoffMaxAgeSeconds`; a consumed handoff, renamed `.consumed`, is not fresh). No fresh handoff: stop, `no-handoff`; this is also how a deliberate `/exit` ends the loop. A fresh one: continue. (4) Progress check, below. (5) If `restarts` has reached the maximum, stop `max-restarts`; if `noProgress` has reached the breaker, stop `breaker`. (6) Wait the backoff, start the command again with the restart prompt appended as its last argument, increment `restarts`, go to 3. The first start never gets the prompt.
note: **progress.** A run made progress when the handoff it ended with was written when or after the run started (mtime not earlier than `runStartedAt`, which is taken just before the spawn, so a coarse filesystem timestamp cannot hide a handoff written at once) and its SHA-256 differs from `lastHandoffSha`, the handoff the run began with. For the first run that is the handoff present when `run` started, if any. Progress resets `noProgress` to 0 and stores the new sha; anything else adds one. This is what the circuit breaker counts: a restarted orchestrator that dies before consuming the handoff (bad auth, a hook error, a crash on boot) leaves the same fresh file behind, and without this check the loop would restart it until `max-restarts`. `noProgress` is therefore not "restarts without a handoff" (those stop at step 3) but "restarts that left no new handoff".
note: **signals.** SIGINT and SIGTERM to the supervisor are forwarded to the child and set `interrupted`; the supervisor then waits for the child, does not restart, and stops. A Ctrl-C in the pane reaches both (same process group), so the supervisor ignores SIGINT for itself and relies on the forward. SIGKILL cannot be handled: the lease then goes stale (the holder is gone) and `rota reap --kind lease` clears it, as for any dead orchestrator.
note: `--first-prompt` (#19) is appended as the last argument of the first start only, where `--prompt` goes on restarts; unset, the first start is `<command>` alone. `rota orchestrate` uses it to start the agent on `/rota-orchestrate` without the restart prompt landing beside it as a second positional argument. `--config-dir` sets the child's `CLAUDE_CONFIG_DIR` from the first start (and is the account a usage switch leaves); `rota orchestrate` passes it so the account survives a tab whose environment comes from the multiplexer server.
note: `changed` is true once a child was started. A `--json` run raises its warnings (escalation not sent, no `escalateIssue`, a reclaimed stale lease) in the envelope and on stderr.
note: **on stop** the supervisor releases the lease it holds (a stopped round needs no orphan lease, and a human can start an orchestrator at once), writes `status: "stopped"` and `stopReason`, and on `max-restarts` or `breaker` sends the escalation below. Releasing is skipped when the lease is no longer this supervisor's.
note: **breaker notification (C4).** On `max-restarts` and `breaker`, `run` calls `round escalate send` (the library entry, not a subprocess) on the issue `orchestrator.escalateIssue`: title `Orchestrator keepalive stopped: <stopReason>`, body with the restart and no-progress counts, `lastExit`, the handoff path and age, the state file path, and the line `Run rota keepalive run again after fixing the cause; the handoff is kept.` The escalation id goes in `data.escalation` and the state file. With `orchestrator.escalateIssue` unset (0) there is no thread to post on: `run` raises the host notification alone (`Notify`, herdr only), records `escalation` absent, and adds a `warnings` entry saying why. A pending escalation already on that thread (`send` exits 4) is a warning too; the stop stands. `no-handoff` and `interrupted` send nothing: they are the human's own act.
note: **the handoff is never deleted by the supervisor.** Only D1's SessionStart hook consumes it (rename), which is the one place that knows the injection happened.

### rota keepalive status
rota keepalive status
repo: none
data: {"running": bool, "lease": {"state": "none" | "live" | "stale" | "foreign", "holderPid"?: number, "round"?: number}, "keepalive"?: object}
exit: 3 when there is no project root; 5 when git fails
old: none (new in D2)
note: read-only, no `changed`. `keepalive` is the state file as stored, absent when none exists; `running` is true only when the file says `running` and its `pid` is alive (a SIGKILLed supervisor leaves `running` on disk, so the pid is checked). It reads the lease through `round.ReadLease`, the reader `reconcile` and `reap` use.

#### Config
Five keys under `orchestrator`, all silent defaults (not seeded by init), validated where read like D1's (out of range exits 70 for verbs that read them; `run` uses 70): `keepaliveMaxRestarts` (integer, 0 or more, default **10**; 0 means no restarts, so a first handoff-exit stops with `max-restarts`), `keepaliveBreaker` (integer, 1 or more, default **3**), `keepaliveBackoffSeconds` (integer, 0 or more, default **5**), `restartPrompt` (non-empty string, default `Continue as orchestrator: read the handoff injected at session start, run rota round status, and resume the round.`), `escalateIssue` (integer, 0 or more, default 0, meaning unset). Documented in the five places the project rules name.

#### Tests (acceptance → check)
Every test drives `run` with a fake child, a shell script under `mktemp -d` that writes or withholds a handoff and exits, and a fake `gh` for the escalation; the Go tests inject spawn, clock and lease env into `internal/keepalive` (new). No real `claude`.
- Exit with a fresh handoff restarts it: the child writes `.rota/handoff/<base>.md` and exits; a second start happens, with the restart prompt as the last argument and none on the first.
- Exit without one does not restart: `stopReason: no-handoff`, exit 0, one start only, lease released.
- A second orchestrator cannot start while the lock is held: a second `run` exits 4 `lease held` while the first lives; a hand-run `rota round start` from a non-descendant is refused as in C3; one from the child under `ROTA_ROUND_HOLDER_PID` renews.
- The breaker trips after N no-progress restarts and notifies: a child that exits at once leaving the same fresh handoff gives `breaker` after N restarts, exit 1, an escalation comment on the fake forge, `data.escalation` set; with `escalateIssue` unset, no comment and the warning.
- Also: `max-restarts`; progress resets the counter (a child that writes a different handoff each run never trips the breaker); SIGINT forwards, does not restart; a SIGKILLed supervisor leaves a stale lease that a new `run` reclaims; `status` before, during and after.
- Gate: `internal/keepalive`, `internal/roundlease` (the `Discover` env), `internal/round` (`start` numbering a pre-taken lease), `internal/config`, `internal/cli`, `cmd/rota`; smoke section 91.

#### Rulings and what is still mine
Ratified (round 4): the supervisor instead of an external watcher; the supervisor holding the lease through `ROTA_ROUND_HOLDER_PID`; the thread for the breaker left unset by default; the restart prompt as the last argument with the default text in Config.

The departure from #66, stated for the PR and for the C7 skill's restart note: the issue says to watch for the exit through herdr's process-info PID or `agent_status_changed` and restart in the same pane. D2 instead runs the orchestrator as the supervisor's child, so the supervisor is its parent and reads the exit status from `wait`. The cost is that an orchestrator not started as `rota keepalive run -- claude …` is not covered, and a restarted one reaches its handoff through D1's SessionStart hook without `rota round start` first, because the supervisor already holds the lease.

My own calls, unratified: defaults 10 restarts, breaker 3 and backoff 5 s (unmeasured; a restart costs a handoff-sized context reload, so the maximum is a budget as much as a fault bound); progress by handoff SHA (a restarted orchestrator that makes real progress but leaves an identical handoff counts as stuck, which I judge rare and cheap); the shape of the state file.

Not in D2: usage-limit sleep or account switch (D3, which keeps its log in `limits` in `.rota/workers.json` and runs its loop inside `run`), a watcher for orchestrators not started under `run`, restarting workers, and any change to what D1's hooks decide.
