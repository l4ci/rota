# Acceptance marks (`/rota-work` Step 7, issue backend)

Loaded by `SKILL.md` Step 7, issue backend only.

after recording PASS proof, read `rota item show <ID>` and `rota proof show <ID>`. Mark each verified criterion with `rota plan pass <ID> AC-n --proof '<sha>:<check>'` (use `'#2150'`, for example, as the issue key), using that PASS row's sha and check. Repeat per resolved item, including open bundle members, before closing or shipping; proof rows alone do not mark criteria. Leave an unmet criterion unmarked and state its id and reason. A round worker reports `rota worker done <slot> --outcome partial --summary-file <f>`, with each unmet id and reason on the summary's third line (`failed` if nothing can be delivered). A plain done or `--outcome done` refuses while an explicit criterion on a tracker item the PR closes is unmet. Non-closing `Refs` slices and file-mode items keep their existing done flow. For an intentional close with unmet criteria, the merger uses `rota item complete <ID> --commit <sha> --unmet-reason <text>` to record the gaps and reason; the gate skips acceptance for the closed issue. Round workers never close items to clear the refusal. Items without explicit `AC-n` ids keep their existing flow.
