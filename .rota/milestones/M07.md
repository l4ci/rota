# M07 — Issue-tracker backend

## Goal

Setting `backlog.backend: "issues"` makes GitHub/GitLab issues and native milestones the single source of truth for hv work items, with each item's context in its comments; the default `"file"` backend stays byte-identical. Design: `.hv/designs/F82.md` (item [F82]).

## Acceptance criteria

- With `backlog.backend: "file"` the full existing smoke suite passes unchanged.
- With `backlog.backend: "issues"` on both GitHub and GitLab: capture → next → work → review-queue merge → release runs end-to-end against the fake CLI, and once by hand against a real repo.
- A fresh session resumes an item from the issue and its comments alone.
- A rate-limit 403 stops the run with a report; never a retry loop.
- `/hv-migrate issues --dry-run|--apply` round-trips this repo's own open backlog.

## Rationale

Issues make the backlog visible and shareable outside the repo checkout, give every item a durable comment thread any later session can resume from, and let the tracker's own PR/milestone machinery drive review and release. The hvlib backend seam keeps the file mode untouched for users who don't want it.

## Open risks

- GitHub secondary rate limits under parallel rounds (claim = 3–5 writes).
- GitLab project setting can disable auto-close; non-default-branch merges never auto-close.
- Latency with no cache (one list + view-with-comments per `/hv-next`).
- Umbrella scope (S06) is the largest single slice.
- Two ID shapes (`F82` / `#42`) leaking into skill prose.

## Research findings

- Secondary limits: 80 content-creating requests/min, 500/h; back off on `retry-after`, else ≥60 s; retrying during lockout extends it — https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api ; https://github.com/ComposioHQ/agent-orchestrator/issues/1083
- `gh issue list` defaults to 30 results; GitLab notes page at 20 — always paginate, warn when result count equals limit — https://cli.github.com/manual/gh_issue_list
- Auto-close only on merge to the default branch; GitLab keywords Close/Fix/Resolve/Implement, can be disabled per project — https://docs.gitlab.com/user/project/issues/managing_issues/
- Comment edit in place is REST-only: GitHub `PATCH /issues/comments/{id}` (65,536-char cap), GitLab `PUT /projects/:id/issues/:iid/notes/:note_id`.
- Prior art: ccpm runs issue-as-truth for Claude Code (https://github.com/automazeio/ccpm); Copilot coding agent output quality tracks issue readiness and it re-reads discussion on resume (https://github.blog/ai-and-ml/github-copilot/assigning-and-completing-issues-with-coding-agent-in-github-copilot/).
