# M06 — v4.1: umbrella-aware persistence

## Goal

Close the umbrella gap left open in v4.0: per-sub-repo .hv/knowledge/<repo>/KNOWLEDGE.md storage with hybrid umbrella+sub-repo routing, so umbrella users running /hv-migrate v4 no longer hit F19's explicit refusal. DECISIONS.md stays umbrella-only by architectural commitment.

## Acceptance criteria

Derived from F21's design + detail (`.hv/designs/F21.md`, `.hv/features/F21.md`):

- Per-sub-repo `.hv/knowledge/<repo>/KNOWLEDGE.md` storage works for `/hv-learn` writes; umbrella-shared `.hv/KNOWLEDGE.md` retained for cross-repo learnings.
- All five `hv-knowledge-*` helpers (merge, query, index, tier, amend) handle umbrella scope: `--repo umbrella|<name>` with auto-resolve fallback; target resolution centralized in a new `hvlib` function.
- `hv-knowledge-query` reads umbrella + active-sub-repo files when run inside a sub-repo (with `> from:` prefix); umbrella-only at umbrella root unless `--repo` given.
- Tier sidecar split per-sub-repo, symmetric with the data-file split.
- CLAUDE.md managed-block per sub-repo lists umbrella + own topics; single-repo projects unchanged.
- `/hv-migrate v4` umbrella branch stops erroring: migrates each `.hv/contexts/<repo>/CONTEXT.md` into the right per-sub-repo KNOWLEDGE.md Glossary; tested against a synthetic umbrella fixture.
- `references/persistence-skills.md` (and any successor scoping ref) documents the hybrid model; DECISIONS.md stays permanently umbrella-shared.
- New smoke section covers umbrella write / read / query / migrate end-to-end.
- **No partial ship** — every criterion above lands before the v4.1 tag.

## Rationale

v4.0 (M01) intentionally deferred umbrella-aware KNOWLEDGE: `/hv-migrate v4` errors on umbrella projects rather than mishandling them (B09, shipped). That deferral is a one-release gap, not a permanent one. v4.1 closes it so umbrella users get coherent term + learning storage that respects repo locality. Splitting from v4.0 keeps M01's "no partial ship" bar honest — umbrella infra is distinct work, not a fold.

## Open risks

- This repo has **no umbrella state** — F21 can't be dogfooded here; needs a synthetic umbrella fixture for tests.
- F21's design (draft, 2026-05-16) references F18-removed code (`hv-context-add`, `references/context-umbrella-scoping.md`). The plan must reconcile its "mirror hv-context-add" anchors against the post-F18 `/hv-learn --term` + `hv-glossary-write` shapes — the codebase is ground truth, not the design's stale references.
- Hybrid query semantics (umbrella + active sub-repo merge) and `hv-knowledge-amend` cross-file `(topic,title)` collisions need careful disambiguation rules.
