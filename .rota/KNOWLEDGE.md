## Architecture: Helper conventions & invariants: Go verbs & fakes: Test fakes & isolation

- **cli tests share one XDG_CONFIG_HOME pinning test.slots** — Every internal/cli test shares one process-wide XDG_CONFIG_HOME, and TestMain pins `test.slots` 1 there; init tests rely on that pin since #4092 seeds test.slots. `rota setup` runs runInit but is not seeded, so its global-offer tests still assert nothing is written (#4092). <!-- paths: ["internal/cli/*_test.go"] --> <!-- 2026-11-22 -->
- **Raw go test can hang on the slot TMPDIR** — Inside a worker slot, TMPDIR points at .rota/tmp/slots/<slot>, under the main checkout, and a raw `go test` of internal/cli can hang there. Run package tests through `rota test run` or with `TMPDIR=/tmp` (reported on #4069). <!-- 2026-11-21 sha:cbff24fc -->
- **Call wire before pool in round assign fixtures** — In internal/round tests, assignFixture.pool installs the account pool via Env.WithAccounts and wire rebuilds env.Worker from ws, dropping it. Call wire (e.g. to swap NewHost) before pool, or poolEntries panics on a nil *Accounts. (#3471) <!-- 2026-11-18 sha:fccc9ce3 -->
- **Every test-built rota binary needs -tags rotatest** — Since #3364 the ROTA_TEST_NOW, TODAY, HOLDER_PID and LATEST_VERSION overrides exist only under the rotatest build tag. A test that builds its own binary and sets one of them needs -tags rotatest (cmd/rota/scenarios_config_test.go missed it and every update scenario went red); smoke section 169 builds untagged on purpose to pin the production path. <!-- paths: ["cmd/rota/*_test.go","test/lib.sh"] --> <!-- 2026-11-16 sha:5f969fa9 -->
- **Test Wait sequences through e.Wait, not recordRow** — Wait dedups returned rows by seen key (state, evidence, relay count, event seq), so a promoted DONE and the later real ROTA-DONE for the same PR share a key and the second never reaches recordRow. Anything that must happen on the real done cannot live only behind that gate; test such sequences through e.Wait with the gate world fake forge (newWorld plus w.forge), since calling recordRow directly skips the dedup and passes while production fails (#3320). <!-- paths: ["internal/worker/wait.go","internal/worker/poll.go"] --> <!-- 2026-11-16 sha:5f969fa9 -->
- **internal/testiso stays import-free** — test/fast_tree_scans_test.py copies internal/testiso/nested.go alone into a minimal module, so any rota import there fails `rota test run fast` with "no required module provides package". A helper needing a .rota path spells it and goes on literalAllowed in internal/rotatree/leak_test.go (#2499). <!-- 2026-11-14 sha:4d9ab550 -->
- **Reproducing a submitted Core delivery** — To reproduce a submitted Core delivery, use coretest.New(t, "claude-code") with an unsigned task dispatch; the Codex fixture echoes the signed payload, supplies pickup evidence at once and reports picked-up instead. For worker-state-lag regressions keep the real submitted host receipt and set only the saved outcome to unknown; the next dispatch must reconcile to submitted without a second send (TestCoreAdapterSubmittedDeliveryRefusalsAgree). <!-- paths: ["internal/worker/core*"] --> <!-- 2026-11-12 sha:8f7169bc -->
- **Red-train fixtures after alone-run classification** — Since #3095 a red train past its first member reruns the failing tests on the base plus that member alone. Shell fixtures that count verify runs (`countingVerify`, `stopCountingVerify`) count those runs too: expect `first+2`, not `first+1`. A fixture that fails once (`test -f seen || { touch seen; exit 1; }`) no longer yields a culprit: the alone-run passes, so the red is an unreproduced flake that blames nobody. To force a culprit, fail the first two runs with the member merged, as `TestTrainNotesFlakyCulpritAsTransient` does; output with `--- FAIL:` lines also gets the in-tree retry, a third run. Alone-runs use `test.vacuousCommand`, whose default runs real `go test` on the package the output names, so a fixture printing a fake package needs its own `vacuousCommand`. <!-- paths: ["internal/worker/train_test.go"] --> <!-- 2026-11-11 sha:1d6ab2be -->
- **Simulate a prompts upgrade with a second catalog** — `internal/prompts.Open(root, catalog)` takes the section catalog as an argument, so a test simulates an upgrade (changed, unchanged, removed default) by reopening the store with a second catalog. At the CLI layer, where `prompts.Catalog()` is fixed, write a `.rota/prompts.json` with an old `baseline` and its real sha256 `baselineDigest`: the reader rejects a mismatching digest. <!-- paths: ["internal/prompts/**"] --> <!-- 2026-11-07 sha:e2550e4d -->

- **Tree-scan registry for temp-tree walkers** — A Go test that walks a temp fixture tree (filepath.WalkDir over t.TempDir) is discovered by `test/treescan` and joins the fast tier on its own (#3045, nothing refuses it). If it only reads its own temp tree, list it in `test/treescan/registry.json` under `fixtures` with a reason to keep it out of the tier; the registry holds only these exemptions. - **Embedding host fakes must redeclare Capabilities** — Host.Capabilities() is promoted through struct embedding, so a test fake that embeds another fake and adds an optional method (Labeler, TabLister, ...) must define its own Capabilities() returning host.CapabilitiesOf(self); otherwise the promoted one describes the inner value and the new side is invisible to callers (#770). <!-- 2026-10-11 -->

- **A bigger timeout is not a flake fix** — Timing tests in internal/worker that flaked under gate load (#1266) were fixed by stubbing the slow call through the existing Env.Git seam and an injected clock, not by raising deadlines; a raised deadline only moves the flake. Prove a flake fix with go test -race -count=50 while another go test ./... runs as load. <!-- 2026-10-21 sha:6b883b38 -->

- **Isolate the global config without a temp dir leak** — internal/testiso keeps test binaries off the developer's global rota config. An init that keeps an os.MkdirTemp dir leaks one dir per test binary (the gate's leak check fails), and a predictable path in shared /tmp lets another user plant a config. Use MkdirTemp, os.Remove it at once, and point XDG_CONFIG_HOME at a nonexistent child; also unset ROTA_CONFIG_DIR. <!-- 2026-10-21 sha:6b883b38 -->

- **Tests that read slot env must stub Getenv** — Go tests run inside a worker worktree inherit ROTA_SLOT (and other ROTA_* env), so a test whose deps read the real env passes on main and fails in a slot. Stub deps.Getenv explicitly in any test whose outcome depends on slot routing; the git-base test in internal/cli/git_slotbase_test.go is the pattern (#2100). <!-- 2026-10-26 sha:58e0f128 -->

- **Completion tests need the real backlog backend** — `fakeRemote.Complete` in `internal/round` closes an item directly and skips proof and acceptance checks. Tests for completion guards must combine the real `backlog.Issues` backend with `trackertest.Fake`, as `internal/round/accept_acceptance_test.go` does. <!-- 2026-10-27 sha:27346ef -->

- **Set Item.Type explicitly in round tests** — `fakeRemote.add` leaves `Item.Type` empty, so older round fixtures never exercise per-kind templates or readiness. Set the type in new tests and add a real file-backend case; file-mode smoke fixtures are features and need the required headings. <!-- 2026-10-27 sha:27346ef -->

- **Wrappers that embed IssueTracker hide optional interfaces** — A wrapper embedding the narrow `IssueTracker` interface hides optional methods such as `LabelLister` from type assertions. Forward each one explicitly and keep writes behind the wrapper refusal; see `assumedForge` and `TestAssumedForgeLabelsReadOnly`. <!-- 2026-10-27 sha:27346ef -->

- **Verdict fallback tests need mixed kinds and same-sha updates** — `EffectiveReview` takes the last spec or quality record, so recovered PR verdicts of one kind can mask a local verdict of another. Test cross-kind masking and a same-sha report refresh, not only a same-kind cache hit. <!-- 2026-10-27 sha:27346ef -->

- **New terminal hosts need real-adapter round tests** — Adding a terminal host needs a dispatch and round-health test through the real adapter, not only Host-method fakes. On #2203 the Host implementation alone hid three blockers: Codex preflight still required herdr, numeric pool init invented tmux handles, and round Health/Status inferred death from absence in a successful snapshot. A runtime-scoped host must carry unverifiable absence through reclaim, while a forced reclaim still calls the host's process proof. <!-- paths: ["internal/host/**"] --> <!-- 2026-10-27 sha:1e671baa -->

- **Capture host process evidence while the agent lives** — Testing a lifecycle coordinator against a fake KillSlot proves cleanup is requested while hiding that the real host can never satisfy it. For runtime-scoped handles, drive both lifetimes through the actual adapter: native handle lost while retained processes are gone, and agent root exited while an observed child survives. Capture process evidence while the root is alive; a cleanup-time snapshot cannot recover already-reparented descendants (#2203). <!-- paths: ["internal/host/**","internal/round/**"] --> <!-- 2026-10-27 sha:1e671baa -->
## Architecture: Helper conventions & invariants: Go verbs & fakes: Gate & tracker plumbing

- **FailedHeads omits provenance-fail; read gateFailed for every verdict** — `provenance-fail` is not a `failedHeadVerdict`, so it never reaches `Result.FailedHeads` and is regated every tick. A step that must act on any failed gate after the merge (the failed-gate follow-up, #4247) reads `Result.gateFailed`, which keeps every verdict the merge returned at the head it judged; `FailedHeads` only covers stale, verify-failed, vacuous-tests and interaction. <!-- paths: ["internal/roundtick/*.go"] --> <!-- 2026-11-23 sha:93625a9c -->
- **Renaming a tick merge target drops its fill bypass** — Tick wiring state (`wiring.bypass` in `internal/roundtick/wire.go`) is keyed by the merge-target string; `AwaitingReview` and `Head` set `bypass[<slot name>]`. A step that renames a target (assign-ahead swaps a slot name for `#<PR>`) loses the fill bypass unless it maps the alias back, as `Run` does by wrapping `Env.FillBypass` with assign-ahead's alias map. `TrainReady` and `ReadySince` resolve to the PR number first and are safe. <!-- paths: ["internal/roundtick/*.go"] --> <!-- 2026-11-23 sha:93625a9c -->
- **Clear claimId when releasing a landed slot early** — A done slot keeps its registry claimId until it parks, and reconcile rearmClaim re-posts a lost claim for any slot still holding its issue. Post-merge bookkeeping that releases the claim before the park must also clear claimId, or the next reconcile restores it. (#3629) <!-- 2026-11-18 sha:fccc9ce3 -->
- **updateFreeze runs under the caller's land lock** — Only worker Freeze acquires the land lock; freezeLandedFailure and clearVerifiedFreeze run with it already held and the lock is not reentrant, so the shared updateFreeze helper must not take it. A helper that locks would deadlock those two callers. <!-- paths: ["internal/worker/freeze.go"] --> <!-- 2026-11-17 sha:0bb55d8a -->
- **Ledger rows take the lease's round only** — worker.CurrentRound takes only the sources its caller fills: LedgerRound passes the lease alone, so a registry round that outlived its lease never stamps new ledger rows (pinned by a test). Round-package callers (claims, relays) read lease, then registry, then ledger, so a claim right after round assign names the new round. <!-- paths: ["internal/worker/currentround.go"] --> <!-- 2026-11-17 sha:0bb55d8a -->
- **A canceled tracker call keeps its cause** — tracker.run used to flatten a canceled parent ctx into a KindInternal string, so errors.Is(context.Canceled) failed and the verb exited 70. tracker.Error now carries Cause, and exitmap maps a tracker error wrapping context.Canceled to 130 without a signal check (#3159). <!-- 2026-11-14 sha:4d9ab550 -->
- **A tick names why it skips a due PR** — roundtick reports a due PR it does not start as a hold (`Result.Holds`, rendered `hold\t<target>\t<why>`), kept apart from NeedsYou on purpose: NeedsYou entries wake the watch and count as New. Merged.Skip members carry a Detail that becomes the hold reason (#3163). <!-- 2026-11-14 sha:4d9ab550 -->
- **Integration branches are remote-only** — A stacked integration branch exists only on the remote, so code that assumes a local base breaks: the train base-is-checked-out check and the gate local rev-parse of the base (stepRefs). Member PRs still target main, so the gate PR-target check takes GateOpts.PRBase. The worker fake forge keeps one primary PR; per-PR state#N / base#N words describe a second one. <!-- paths: ["internal/worker/**"] --> <!-- 2026-11-12 sha:8f7169bc -->
- **Close order is comment, label, then state** — Every tracker adapter closes in the order comment, not-planned label, then state. Jira, Linear and Itsaplan used to close first so a retry would not double-comment; that trade was reversed. To test a failed comment write, close_contract_test.go puts a failing reverse proxy in front of the HTTP fakes, so no fake needs editing. A retry of closeAfterMerge after a permanent state-change failure reposts the note; this is accepted and documented there. <!-- paths: ["internal/tracker/**"] --> <!-- 2026-11-12 sha:8f7169bc -->
- **Skill install roots come from worker.SkillClaudeDirs** — internal/skills cannot import config or worker, so the Claude config dirs a skill install spans (current dir plus round.accounts dirs) are enumerated once in worker.SkillClaudeDirs; skills.InstalledRoots and InstalledBrief take (home, claudeDirs, top) and round builds them through Env.skillInstalls (#3024). A new reader of installed skills takes the dirs as an argument rather than reading CLAUDE_CONFIG_DIR itself. <!-- 2026-11-11 -->
- **Verdict call sites resolve the sub-repo key** — Verdict readers take a []Record list; pick it with Store.Branch(repo, branch). In internal/cli, branchVerdicts(c, root, branch) resolves the sub-repo the way the gate does (shipVerdict(c, root, root).Repo). A new call site that spells BranchKey("", ...) outside a single-repo entry point reads the wrong key in an umbrella; the autopilot readiness gate did exactly that until #3033. <!-- 2026-11-11 -->
- **Local-path remotes classify by the whole path** — `tracker.ProviderFromURL` classifies a local-path remote by its whole lowercased path, so `/srv/mirrors/github-r` reads as github: `remoteurl.Parse` returns Host "" for a path and the fallback lives in `RemoteHost`. Golden files can freeze a classifier bug (TestReleaseHostParity once pinned `https://user@github.com/...` as github-enterprise); regenerate them when the classifier is fixed. <!-- paths: ["internal/tracker/*.go","internal/remoteurl/*.go"] --> <!-- 2026-11-09 sha:b0a632a5 -->
- **Cancelled verify looks like a red verify** — Under a cancelled context `runVerifyCmds` returns no error: each killed command comes back as exit 127 in `Failed`, an ordinary red verify. Check `ctx.Err()` before treating a verify result as a finding (bisect, flake record, cache blame, culprit). `signal.NotifyContext` swallows SIGINT/SIGTERM for the whole verb, so every wait must watch ctx: use `fsio.LockedCtx`, not `fsio.Locked` (a queued train ignored a signal for up to `landLockTimeout`, 4h). <!-- paths: ["internal/worker/**"] --> <!-- 2026-11-07 sha:e2550e4d -->
- **Shield a step from cancel on both e.Ctx and ctx** — `Env.git` and the other `internal/worker` helpers run on `e.Ctx`, not the ctx a stage receives. To shield a step from cancellation (train member landing, ledger write after cancel): `shielded := e; shielded.Ctx = context.WithoutCancel(e.Ctx)` and pass `context.WithoutCancel(ctx)`. Shielding only the argument leaves git calls failing on the cancelled `e.Ctx`. <!-- paths: ["internal/worker/**"] --> <!-- 2026-11-07 sha:e2550e4d -->
- **Telemetry ledger kinds are skipped in ledger.Fold** — A ledger kind that is telemetry, not a round lifecycle event (here `verification`), must be skipped in `ledger.Fold` (internal/ledger/summary.go), or the round first/last timestamps and per-slot folds pick up gate-time rows. Cached and CI verify results carry no duration (`VerifyResult.WallSeconds` is nil): report them as unavailable, never zero. <!-- paths: ["internal/ledger/**"] --> <!-- 2026-11-07 sha:e2550e4d -->
- **GateOpts.ReviewsOnly still writes; use Observe** — `worker.GateOpts{ReviewsOnly: true}` is not read-only despite implying CheckOnly: stepRefs runs `git fetch <remote>` and stepVerdictReports recovers PR verdict reports into `.rota/verdicts.json`. A caller that must not write (`round tick --observe`) sets `GateOpts.Observe`, which skips both and judges last-fetched refs and local verdicts only. <!-- paths: ["internal/worker/**"] --> <!-- 2026-11-07 sha:e2550e4d -->
- **Read paths in internal/round are not all read-only** — `closedSinceReview` seeds the review timestamp and caches the closed count in workers.json, `git status` may refresh the index, and stale-claim dating fetches. A read-only caller needs an explicit mode (the `inspectReads` / `persist` switches from #2579), not just skipping the repair. <!-- paths: ["internal/round/**"] --> <!-- 2026-11-07 sha:e2550e4d -->
- **A per-invocation cache must reset per pass in long-running verbs** — The forge read cache (tracker.ReadCache, #547) lives for one rota invocation, but round watch and the autopilot are one invocation running for hours, and their forge polls only read, so nothing clears it. Any loop that re-reads the forge calls Deps.freshReads() at the start of each pass. A new long-running verb that polls the forge must do the same, or it serves its first answer forever. <!-- 2026-10-08 -->

- **Gate target fields change mid-run** — Gate steps refine the target as they run: stepExternal replaces Branch with the forge's head and stepAdoptPR adopts a PR the slot never recorded. Anything derived from the target (issue via HeldID, approval thread via PR) must be recomputed where those inputs change; freezing it at resolution silently skipped closes/review-depth/best-of for external PRs and sent adopted-PR approvals to the issue thread (#795). <!-- 2026-10-12 -->

- **Gate steps read the forge only after stepRemote** — A gate step that calls the forge must run after stepRemote and skip when the gate does not read origin refs: smoke 68(h) requires zero forge traffic for a recorded PR without an origin remote, and a gh pr view in an earlier step fails it (#817). <!-- 2026-10-15 -->

- **The tracker REST layer never resends a POST after a 5xx** — internal/tracker/rest.go retries 429 for every method but 5xx only for GET/HEAD/PUT/DELETE, since a POST that hit a 5xx may already have created a comment or issue. Read-only GraphQL goes through REST.Query, which retries and refuses a mutation document (#809, #813). <!-- 2026-10-15 -->

- **The worker forge must not share the read cache** — `Deps.workerEnv` wires `worker.Env.Forge` with `d.TrackerOptions` only, never `trackerOptions()` with the `ReadCache`: the gate retries `PRMergeable` (`gh pr view`, a cached read) until GitHub computes it, the CI verifier polls `CommitChecks` (an `api` GET, cached) until checks settle, and PRView is re-read after a stale-merge push; nothing inside a gate run calls `freshReads`, so a cached first answer kills the retry and stalls CI mode to verify-timeout. `TestWorkerEnvForgeSkipsReadCache` pins it (#888, round 25). <!-- 2026-10-19 -->

- **Typed stage handoffs copy slices and move cleanup ownership** — From the #2450 stage-runner refactor: a typed handoff can still share mutable slice storage, since appending to a caller's Notes wrote through spare capacity (TestGateSlotHeadStageOwnsNotes); give each operation its own writable result slices, including train Members. A stage that creates a resource keeps cleanup ownership until its normal return hands the handle over, or a panic during planning leaks the scratch worktree (TestTrainPlanPanicLeavesNoScratchTree). Test both sides of that transfer. <!-- 2026-11-01 sha:f5399270 -->

- **GateResult.OK stays narrower than CLI success** — postgate.Gate uses GateResult.OK() to clear landing bookkeeping and roundtick treats it as a new landing, so a success that lands nothing (already-merged) is handled explicitly in the CLI envelope rather than by widening OK(). Test the command envelope as well as the worker verdict (smoke section 68). <!-- 2026-11-01 sha:f5399270 -->
## Architecture: Helper conventions & invariants: Go verbs & fakes: Verb registration & guards

- **No os.TempDir in verb code** — Verb code in internal/cli may not call os.TempDir: the TestNoRawMachineReadsOutsideDeps tripwire rejects it. Temp locations come from rotatree.TempRootVia, so with no project root a verb can only skip its temp write (e.g. proof record skips the FAIL log), never fall back to the system temp dir (#4004). <!-- paths: ["internal/cli/**"] --> <!-- 2026-11-21 sha:3f0c785e -->
- **Symlink guards must keep the original path spelling** — Parent-path extraction for a symlink guard must not clean the path: path.Dir and filepath.Dir resolve link/.. before the walk can inspect link. Keep the substring before the last slash; TestSymlinkIn/nested/link/../file pins it. (#3749) <!-- 2026-11-18 sha:fccc9ce3 -->
- **Leaf packages keep kind lists pinned by a seam test** — config and connections sit below tracker in the import graph and cannot read ownKinds, so issueSources, connections.Kinds/Validate and config key rows stay leaf lists. TestOwnKindsWiredEverywhere (internal/tracker) fails when they drift from the registry. (#3776) <!-- 2026-11-18 sha:fccc9ce3 -->
- **Descriptor tables calling New must be built in init** — A package-level var literal for a kind descriptor table fails with an initialization cycle when a descriptor closure calls New(), because New reads the table. Build the table in init() (internal/host/policy.go). (#3765) <!-- 2026-11-18 sha:fccc9ce3 -->
- **Arithmetic expansion falls back to command substitution** — Bash runs $((…)) as a command substitution when the paren opened right after $(( closes before the final )). internal/shlex uses that structural rule (no text heuristic), so forms like $((true) && (git add -A)) reach the guard while real arithmetic stays allowed. (#3761, PR #3825) <!-- 2026-11-18 sha:fccc9ce3 -->
- **Prose flags of safe programs need the explicit guard list** — The guard opaque path parses any spaced argument mentioning git as a script, so prose flags of known-safe programs go in rotaProseFlags (internal/hook/guard.go). rg is a data program only without --pre, and a value-taking option can swallow --, so the --pre scan must not stop at --. (#3631) <!-- 2026-11-18 sha:fccc9ce3 -->
- **Harness names stay inside internal/harness** — Naming "claude" or "codex" outside internal/harness trips TestNoKindNamedOutsideHarness, so transcript-usage parsing lives in harness.TranscriptUsage and ledger imports harness. Worker metering finds kinds via UsageMeter() (meterKinds, internal/worker/account.go) and builds rows per harness Accounts adapter; Accounts.Meters rides the Quotas 5-minute reading cache (meterTTL, internal/worker/quota.go), so tests that change usage between reads need a clock skew (#3974). <!-- 2026-11-14 sha:4d9ab550 -->

The fence fails closed: `roundcfg.MayRun` refuses an unclassified verb on a support machine, so a verb with no `Fence` is unusable there and no test catches it (`TestGatePoliciesMatchOldTables` only pins the old classes). Bare `rota` declares `fenceAllowed` on the root. Verbs that write only gitignored state are allowed. <!-- paths: ["internal/cli/*.go"] -->  A new fenceAllowed verb must also join oldSupportAllowed in internal/cli/gates_policy_test.go: TestGatePoliciesMatchOldTables fails with `Fence = 3, want 0` otherwise; `-run Gates` does not select it, the name is GatePolicies (#2499). <!-- 2026-11-09 sha:b0a632a5 -->
- **Sanitize text from tracked prompts.json** — `.rota/prompts.json` is tracked, so a cloned repo controls every string in it (section names, baselines, overrides, placeholders echoed in errors). Human-mode output or errors built from store text go through `tui.Sanitize` (`promptText`, `promptsErr` in internal/cli/prompts.go); plain text let ESC/BEL through where `json.MarshalIndent` had escaped them by accident. Pinned by `TestPromptsTextStripsTerminalEscapes` and `TestPromptsErrorStripsTerminalEscapes`. <!-- paths: ["internal/cli/prompts.go"] --> <!-- 2026-11-07 sha:e2550e4d -->

User-sourced text (team report overrides) must go through `codexInstructionTOML`: a raw `"""` closes the string and lets the rest set agent options, and a backslash escapes the next char. `TestCodexAgentInstructionsTOMLRoundTrip` proves it with python3 `tomllib`. <!-- paths: ["internal/harness/codex.go"] --> <!-- 2026-11-07 sha:e2550e4d -->

A reviewer checking a grep-gate or exclusion-list change must copy the export to a scratch dir, `git add -A && git commit`, and run the script on that copy (#4085 nearly merged a gate-breaking test file this way). <!-- paths: ["test/grep-gate.sh"] --> <!-- 2026-11-21 sha:cbff24fc -->
- **Ask reviewers for regression-risk minors** — Delegated reviewers grade a missing test for a wiring line or a narrower-than-intended match as minor/non-blocking, and the autopilot merges CONCERNS within minutes. Ask every reviewer to list non-blocking findings that could reintroduce the bug the issue fixes, and bounce those with `round bounce --force` before re-arming the watch (round 66: #4007 origin/<base> merges, #4008 and #4011 untested wiring). <!-- 2026-11-21 -->
- **Renamed Go tests can silently stop running** — Go runs only functions named Test followed by a non-lowercase rune, so a rename like TestSlotWorktree to TestslotWorktree (from unexporting slotWorktree) drops the test with no error and the suite stays green (#745). Go 1.24+ vet (run by go test) rejects the name, but go.mod pins go 1.22, so this repo gets no warning. When a diff renames a Test func, check it still runs: go test -run '^TestName$' -v must list it. <!-- 2026-10-11 -->

- **Packages before -run in review test commands** — In a reviewer brief, list every package before `-run`: `go test ./a ./b -run X`. With `go test ./a -run X ./b ./c`, the packages after the flag are passed to the test binary as arguments and never run, so a reviewer reports tests it did not run. <!-- 2026-10-22 -->

- **Cross-harness Codex runs here need the unsandboxed rerun and a ChatGPT-account model** — On this host codex exec --sandbox read-only fails with bwrap: loopback: Failed RTM_NEWADDR, so a release or review range run replies UNAVAILABLE and takes the one --dangerously-bypass-approvals-and-sandbox rerun in the scratch extract with the repo guard. The heavy tier default gpt-6-astra is refused on a ChatGPT account; pass the model the Codex workers run, as -m "$M" in two words, since zsh keeps -m gpt-6.1-sol as one argument. <!-- 2026-10-22 sha:d6935d5f -->

- **Reviewer briefs ask for smoke and guard-test impact** — Three round-47 PRs passed all three reviewers and then failed the merge gate: a new forge lookup in worker done ran real gh pr list from smoke section 121, section 68 still expected the old pr-mismatch verdict, and a cli test named a kind literal that TestNoKindNamedOutsideHarness rejects. Spec briefs should tell the reviewer to grep test/sections for every verb, verdict and message the diff changes, check any new forge or host call is reachable only through a fake, and run go test ./internal/harness -run TestNoKindNamedOutsideHarness when a test compares harness kinds. <!-- 2026-11-01 sha:f5399270 -->
## Rounds: Orchestration: Reviews & verdicts: Verdict records & lenses

- **ForHead keeps stale local records** — verdict.ForHead head-filters only recovered reports, so Latest(ForHead(...)) can accept a record at an older sha. ## Rounds: Orchestration: Reviews & verdicts: Bounces & re-reviews

- **Re-review diffs: fix commits only; every branch lens re-records** — `rota review package <branch> --since <sha>` takes in every main merge since that sha, which came to 300 KB on a 3-commit fix in round 58. For re-reviews, put `git show -U8 <fix commits>` in `.review/fix.diff` and give big generated files (frozen jsonl) as `git show --stat`. Separately, the train asks for a `review-<lens>` record at the new head for every lens the whole branch triggers, even when the fix range does not touch the lens path. So rerun each triggered lens on the fix range before training, or the train refuses. <!-- 2026-11-13 sha:f0525c8b -->
- **Check the PR head before a re-review** — A worker can report done with fix commits only local; `verdict add` then refuses the sha as ahead of origin. Compare `gh pr view --json headRefOid` with the head you prepared before dispatching the re-reviewer, and relay a push request if they differ. <!-- 2026-11-07 sha:e2550e4d -->

- **Gate records gaps first and refuses once** — Gate record checks (outcome, provenance, sections, acceptance, review) record a gap and continue; stepGaps refuses once after stepReviewDepth. gapsFirst lets an earlier gap override a later hard refusal, matching the old stop-at-first order; provenance runs after stale, so it pairs only with verdict-blocked. - **Bounces are counted by review verbs, not the gate** — No gate or train verdict counts a bounce or parks a slot (#2858): `internal/postgate` `notify` only posts the PR notice, idempotent per head, and a landed PR clears the item's bounce count. ## Rounds: Orchestration: Gate, trains & bookkeeping: Trains

- **Flaky-red train fixtures need one more failing run** — Since #3647 the train runs the member, its in-tree retry and a whole-tree re-run before bisecting. A fixture faking a flaky red with a fail-first-N counter needs N+1, or it lands on the flaky path instead of the culprit path. <!-- 2026-11-18 sha:fccc9ce3 -->

- **Tree-scan registry conflicts only show on the merged tree** — Since #3045 test/treescan/registry.json lists only fixture exemptions (the scan tier is derived by discovery), and TestRegistry fails the merged tree on a stale fixture entry. Two PRs that merge cleanly can still disagree: one removes or renames a test the fixtures list (round 50: #2731 and #2730 both went red in the train). Merge main into the branch, run go run ./test/treescan --check, drop the stale fixture entry, in sorted order. <!-- paths: ["test/treescan/registry.json"] --> <!-- 2026-11-05 sha:c040959e -->

- **FailingTests needs go test FAIL lines** — `gotestout.FailingTests` returns no names unless the output ends in go test's `FAIL` line and has `--- FAIL: Name` lines. A shell-based train verify fixture needs both, or `TrainFailure.Tests` stays empty. <!-- paths: ["internal/worker/train*.go"] --> <!-- 2026-11-07 sha:e2550e4d -->

- **Train --land-green lands green, not lo** — In `bisectTrain` (internal/worker/train.go) the bisect bound `lo` is not the landable count. Once a red prefix can count as "does not reproduce the original failure" (diagnostic-only failures), `lo` can sit on a red tree. `--land-green` must land only the longest prefix that really ran green (`green`), never `lo`. <!-- paths: ["internal/worker/train.go"] --> <!-- 2026-11-07 sha:e2550e4d -->

- **Train rerun selects top-level test names** — `gotestout.FailingTests` returns subtests as `Parent/sub`, and `go test -run` splits its pattern on `/` per level, so `^(Parent/sub)$` breaks at the paren. `classifyRed`'s `testsCommand` cuts each name at the first `/`. Packages come from go test's `FAIL\t<pkg>\t` lines; a shell fixture that wants `{packages}` filled must print one. <!-- paths: ["internal/worker/train_classify.go"] --> <!-- 2026-11-11 sha:1d6ab2be -->

- **Roundtick train outcomes default to a bounce** — `roundtick` `Env.train` falls through to a default that holds the member at its head and reports a bounce. A new train result that should blame nobody (base-moved, bystander, flake) needs its own `Skip` case before that default, and its flag copied through `trainOutcome` in `internal/roundtick/targets.go`. The tick never reads `worker.TrainResult` directly (#3113). <!-- paths: ["internal/roundtick/tick.go"] --> <!-- 2026-11-11 sha:1d6ab2be -->

- **Don't hand-train while the autopilot is armed** — With rota round watch --autopilot armed, the tick trains reviewed PRs itself, usually before a hand-started rota worker train gets the land lock, which then ends ALREADY-MERGED with nothing landed (round 57, twice). Under the autopilot, review and route; start a train or gate by hand only after switching to a plain watch. <!-- 2026-11-13 -->

## Rounds: Orchestration: Workers & relays: Slots & assignment

- **Adopt an out-of-round PR by cherry-pick** — A PR opened outside the round (e.g. a subagent on a `sub/` branch) cannot be adopted: `round assign --accept-open-pr` refuses a PR owned by no slot and `round transfer` needs a slot already holding the issue. Close the PR and `round assign` with a `--settled-file` telling the worker to cherry-pick the commit onto its own branch (round 68, #4192/#4198/#4202/#4209). <!-- 2026-11-22 -->
- **Same-task dispatch resets the slot's PR and relays** — Slot.Dispatch (internal/worker/slot.go) clears pr and reviewSeen and calls ResetRelays whenever a task is passed, even the task the slot already holds. A relaunch that keeps the assignment (round switch, a recovery dispatch) must capture PR(), Relays() and ReviewSeen() first and restore them, as transfer adopt does. (#3471) <!-- 2026-11-18 sha:fccc9ce3 -->

- **Re-arm the watch after changing round.roster** — A running rota round watch --autopilot keeps the roster it loaded at start. After rota config set --local round.roster to shrink the round, the old watch still assigned the next review to a retired slot and started a new session there (round 50). Re-arm the watch right after any round.roster change, and close a retired slot's terminal only once it holds no work. <!-- 2026-11-05 -->

- **Slot inbox outlives assignments** — `Slot.Dispatch` and `Unbind` no longer delete `inbox`; they mark it read and return pending actionable mail (`endInboxAssignment`). Sequence numbers stay unique via a persisted `inboxSeq` high-water mark, so a test expecting an empty inbox or seq 1 after a new dispatch is wrong. Count obligations with `Slot.Waiting()`/`Pending()`, not `len(Inbox())`. <!-- paths: ["internal/round/**"] --> <!-- 2026-11-07 sha:e2550e4d -->

- **Slot.SetTask is a rename, not an assignment change** — `Slot.SetTask` only renames running work (tracker migration in `migrate.go`, `PromoteBundleLead`, `ReserveSlot` on an empty slot, `round reconcile`). A real assignment change goes through `Bind`, `Dispatch`, `Unbind` or `MarkExternal`, so "assignment ended" logic belongs there, never in `SetTask`; per-task state stamped on records (inbox `task`) must follow the rename. <!-- paths: ["internal/round/**"] --> <!-- 2026-11-07 sha:e2550e4d -->

- **Queued PR records carry their own review cursor** — Parking a slot drops its review cursor (`Slot.Unbind` deletes `reviewSeen`), so polling review input on a queued PR must take the cursor from the record (`QueuedPR.ReviewSeen`, copied in `queuePR`); an empty cursor replays every comment the PR ever got. Records queued before #2580 carry none and are never follow-ups. <!-- paths: ["internal/round/**"] --> <!-- 2026-11-07 sha:e2550e4d -->

- **Transfer sets the review cursor in adopt** — A transfer receiver's review cursor is wiped after the bind step (dispatch resets review state for the new task); the queued PR is handed over afterwards in `adopt` (internal/round/move.go). Set it in `adopt`'s `editSlot` next to `SetPR` (`TransferOpts.ReviewSeen`) so PR and cursor land in one registry write. <!-- paths: ["internal/round/move.go"] --> <!-- 2026-11-07 sha:e2550e4d -->

## Rounds: Orchestration: Workers & relays: Worker sessions

- **herdr-core read has no unwrapped source** — herdr-core `terminal.read` takes only `terminal` and `lines` (history above the screen, default 0); unlike herdr `--source recent-unwrapped` it has no unwrapped source, so a wrapped DONE line reaches the poll classifier wrapped (#4093). <!-- 2026-11-22 -->
- **Read panes with herdr-core read** — Under the herdr-core host, `herdr agent read` and `herdr pane read` fail (they talk to the herdr app socket). Read a worker pane with `herdr-core read <address>`, the address from `rota round status --json` (.data.slots[].address); wrap it in `timeout 20` since a read can hang. <!-- 2026-11-21 -->
- **Per-slot TMPDIR is set at Spawn, not in SlotEnv** — internal/worker/slottmp.go sets TMPDIR (.rota/tmp/slots/<slot>, 0700) in the dispatch Spawn env; SlotEnv also feeds gate behaviour steps and envSetup, which keep their own temp dir.
