## Architecture: Helper conventions & invariants: Go verbs & fakes: Gate & tracker plumbing

- **A canceled tracker call keeps its cause** — tracker.run used to flatten a canceled parent ctx into a KindInternal string, so errors.Is(context.Canceled) failed and the verb exited 70. tracker.Error now carries Cause, and exitmap maps a tracker error wrapping context.Canceled to 130 without a signal check (#3159). <!-- 2026-11-14 sha:4d9ab550 -->
- **A tick names why it skips a due PR** — roundtick reports a due PR it does not start as a hold (`Result.Holds`, rendered `hold\t<target>\t<why>`), kept apart from NeedsYou on purpose: NeedsYou entries wake the watch and count as New. Merged.Skip members carry a Detail that becomes the hold reason (#3163). <!-- 2026-11-14 sha:4d9ab550 -->
- **Integration branches are remote-only** — A stacked integration branch exists only on the remote, so code that assumes a local base breaks: the train base-is-checked-out check and the gate local rev-parse of the base (stepRefs). Member PRs still target main, so the gate PR-target check takes GateOpts.PRBase. The worker fake forge keeps one primary PR; per-PR state#N / base#N words describe a second one. <!-- paths: ["internal/worker/**"] --> <!-- 2026-11-12 sha:8f7169bc -->
- **Close order is comment, label, then state** — Every tracker adapter closes in the order comment, not-planned label, then state. Jira, Linear and Itsaplan used to close first so a retry would not double-comment; that trade was reversed. To test a failed comment write, close_contract_test.go puts a failing reverse proxy in front of the HTTP fakes, so no fake needs editing. A retry of closeAfterMerge after a permanent state-change failure reposts the note; this is accepted and documented there. <!-- paths: ["internal/tracker/**"] --> <!-- 2026-11-12 sha:8f7169bc -->
- **Skill install roots come from worker.SkillClaudeDirs** — internal/skills cannot import config or worker, so the Claude config dirs a skill install spans (current dir plus round.accounts dirs) are enumerated once in worker.SkillClaudeDirs; skills.InstalledRoots and InstalledBrief take (home, claudeDirs, top) and round builds them through Env.skillInstalls (#3024). A new reader of installed skills takes the dirs as an argument rather than reading CLAUDE_CONFIG_DIR itself. <!-- 2026-11-11 -->
- **Verdict call sites resolve the sub-repo key** — Verdict readers take a []Record list; pick it with Store.Branch(repo, branch). In internal/cli, branchVerdicts(c, root, branch) resolves the sub-repo the way the gate does (shipVerdict(c, root, root).Repo). A new call site that spells BranchKey("", ...) outside a single-repo entry point reads the wrong key in an umbrella; the autopilot readiness gate did exactly that until #3033. <!-- 2026-11-11 -->
- **Local-path remotes classify by the whole path** — `tracker.ProviderFromURL` classifies a local-path remote by its whole lowercased path, so `/srv/mirrors/github-r` reads as github: `remoteurl.Parse` returns Host "" for a path and the fallback lives in `RemoteHost`. Golden files can freeze a classifier bug (TestReleaseHostParity once pinned `https://user@github.com/...` as github-enterprise); regenerate them when the classifier is fixed. <!-- paths: ["internal/tracker/*.go","internal/remoteurl/*.go"] --> <!-- 2026-11-09 sha:b0a632a5 -->
- **Cancelled verify looks like a red verify** — Under a cancelled context `runVerifyCmds` returns no error: each killed command comes back as exit 127 in `Failed`, an ordinary red verify. Check `ctx.Err()` before treating a verify result as a finding (bisect, flake record, cache blame, culprit). `signal.NotifyContext` swallows SIGINT/SIGTERM for the whole verb, so every wait must watch ctx: use `fsio.LockedCtx`, not `fsio.Locked` (a queued train ignored a signal for up to `landLockTimeout`, 4h). <!-- paths: ["internal/worker/**"] --> <!-- 2026-11-07 sha:e2550e4d -->
- **Shield a step from cancel on both e.Ctx and ctx** — `Env.git` and the other `internal/worker` helpers run on `e.Ctx`, not the ctx a stage receives. To shield a step from cancellation (train member landing, ledger write after cancel): `shielded := e; shielded.Ctx = context.WithoutCancel(e.Ctx)` and pass `context.WithoutCancel(ctx)`. Shielding only the argument leaves git calls failing on the cancelled `e.Ctx`. <!-- paths: ["internal/worker/**"] --> <!-- 2026-11-07 sha:e2550e4d -->
- **Telemetry ledger kinds are skipped in ledger.Fold** — A ledger kind that is telemetry, not a round lifecycle event (here `verification`), must be skipped in `ledger.Fold` (internal/ledger/summary.go), or the round first/last timestamps and per-slot folds pick up gate-time rows. - **GateOpts.ReviewsOnly still writes; use Observe** — `worker.GateOpts{ReviewsOnly: true}` is not read-only despite implying CheckOnly: stepRefs runs `git fetch <remote>` and stepVerdictReports recovers PR verdict reports into `.rota/verdicts.json`. - **Read paths in internal/round are not all read-only** — `closedSinceReview` seeds the review timestamp and caches the closed count in workers.json, `git status` may refresh the index, and stale-claim dating fetches. - **A per-invocation cache must reset per pass in long-running verbs** — The forge read cache (tracker.ReadCache, #547) lives for one rota invocation, but round watch and the autopilot are one invocation running for hours, and their forge polls only read, so nothing clears it. - **Gate target fields change mid-run** — Gate steps refine the target as they run: stepExternal replaces Branch with the forge's head and stepAdoptPR adopts a PR the slot never recorded. - **Gate steps read the forge only after stepRemote** — A gate step that calls the forge must run after stepRemote and skip when the gate does not read origin refs: smoke 68(h) requires zero forge traffic for a recorded PR without an origin remote, and a gh pr view in an earlier step fails it (#817). <!-- 2026-10-15 -->

- **The tracker REST layer never resends a POST after a 5xx** — internal/tracker/rest.go retries 429 for every method but 5xx only for GET/HEAD/PUT/DELETE, since a POST that hit a 5xx may already have created a comment or issue. Read-only GraphQL goes through REST.Query, which retries and refuses a mutation document (#809, #813). <!-- 2026-10-15 -->

- **The worker forge must not share the read cache** — `Deps.workerEnv` wires `worker.Env.Forge` with `d.TrackerOptions` only, never `trackerOptions()` with the `ReadCache`: the gate retries `PRMergeable` (`gh pr view`, a cached read) until GitHub computes it, the CI verifier polls `CommitChecks` (an `api` GET, cached) until checks settle, and PRView is re-read after a stale-merge push; nothing inside a gate run calls `freshReads`, so a cached first answer kills the retry and stalls CI mode to verify-timeout. `TestWorkerEnvForgeSkipsReadCache` pins it (#888, round 25). <!-- 2026-10-19 -->

- **Typed stage handoffs copy slices and move cleanup ownership** — From the #2450 stage-runner refactor: a typed handoff can still share mutable slice storage, since appending to a caller's Notes wrote through spare capacity (TestGateSlotHeadStageOwnsNotes); give each operation its own writable result slices, including train Members. Test both sides of that transfer. <!-- 2026-11-01 sha:f5399270 -->

- **GateResult.OK stays narrower than CLI success** — postgate.Gate uses GateResult.OK() to clear landing bookkeeping and roundtick treats it as a new landing, so a success that lands nothing (already-merged) is handled explicitly in the CLI envelope rather than by widening OK(). ## Architecture: Skill authoring

- **Re-check generic rules when a skill step becomes a verb** — A rule the model applied with judgment can be unsafe once code applies it without asking. sibling-sweep.md called any path beside a tracked file a sibling; automated in rota work start that would commit config.json.local or main.go.orig, so internal/cycle limits it to .uid, .import and .meta. - **Smoke sections grep skill text where it lives** — Several smoke sections (test/sections/31_brainstorm.sh and others that awk a Step out of a SKILL.md) grep rule text in place. Moving a rule into a sibling reference file is right for skill authoring but fails the gate until the section reads the new owner file; grep test/sections for the moved wording in the same PR. <!-- paths: ["skills/**","test/sections/**"] --> <!-- 2026-10-27 sha:1e671baa -->
- **Skill files live at the top of the skill folder** — embed.go embeds skills/rota-*/*.md and internal/skills/set.go Load skips every skill subdirectory except agents/, so a file in a subfolder (skills/rota-qa/surfaces/web.md, #2065) never reaches rota skills get or install users, and no test catches it. Use flat names (surface-web.md). validate-skills also lets only SKILL.md link extracted files: sibling files name each other in backticks, not links. <!-- 2026-10-26 sha:1df9346a -->
- **Shorten skills structurally, not by rewording** — After one verbosity cut and moving conditional steps into per-skill files, `/concise-writing` passes on skills and references cut only 0.5-1.5% (round 5, #333-#335). The remaining length was duplicated rules and pointer-only sections; a structural dedup (one owner file per rule) cut the references by 10% (#342). <!-- 2026-10-06 -->
- **Codex drops skills whose unquoted description has ': ' or ' #'** — Codex parses SKILL.md frontmatter as strict YAML and silently drops a skill whose unquoted description contains ": " or " #". Claude Code tolerates it. validate-skills.py now rejects those values; use `description: >-` for long or punctuated text. <!-- 2026-10-04 -->
- **Composite-fold deletion scope: orphan helpers + public docs are the predictable miss** — Composite-fold scope undercounting is the predictable failure mode — the rename + link-sweep file list (T4-equivalent) almost always misses two adjacent categories the plan author forgets to enumerate: (1) orphan helpers whose only caller was the gone code (e.g. hv-context-index regenerated CLAUDE.md from .hv/CONTEXT.md, both gone after F18), and (2) public-facing docs about the gone artifact (docs/usage/<thing>.md user guide, docs/reference/<artifact>-md.md format reference). These are NOT "text references to update" — they are whole files to delete. Mitigation: when planning a composite fold, scope the T7 "remove" task with three explicit categories (a) skill folder, (b) plugin/manifest entries, (c) orphan helpers + public-docs deletions; let the T8 "final sweep" catch only TEXTUAL residue, not file deletions. The plan's 16-file rename list is correctly bounded; the deletion list is what gets underestimated. <!-- 2026-05-16 -->
- **Inline-fold drops slash-command surface; composite-fold preserves it as a flag mode** — When retiring a standalone skill, pick the destination shape deliberately. A composite-skill fold (e.g. `/hv-ship --undo` → `/hv-ship --undo`, `/hv-ship --docs` → `/hv-ship --docs`) keeps the slash-command surface as a flag mode and preserves both code paths. An inline fold (e.g. `/hv-map after-work` → `/hv-work` Step 13.7 prose) drops the user-invocable command entirely and embeds the logic at every former dispatch site. Inline folds need one MORE edit than composite folds: every SKILL.md that previously dispatched the gone skill via the `Skill` tool must inline equivalent prose instructions, and the bin helpers' placeholder text and nudge messages that referenced the now-defunct slash-command (empty-set bullets in index helpers, soft-cap-check nudges) need rewording too. Choose inline-fold when the gone skill's manual modes weren't being used; choose composite-fold when at least one manual entry-point still matters. <!-- 2026-05-16 -->
- **Skill folds need quadruple-update: SKILL.md, smoke assertions, references, plugin.json** — When folding standalone skill A into composite skill B as a flag-mode (e.g. `/hv-ship --undo` → `/hv-ship --undo`, `/hv-ship --docs` → `/hv-ship --docs`), four coordinated edits beyond porting the flow itself: (1) smoke-test assertions targeting `<A>/SKILL.md` must retarget to `<B>/SKILL.md` AND match any rewording the port introduced — F17's 'After-work flow' → 'After-work sub-flow' rename invalidated the F09 `grep -q 'Route to the After-work flow'` assertion until updated; (2) architectural reference docs naming the standalone skill (e.g. `references/three-mode-skill-shape.md` 'Used by /hv-ship --docs and /hv-map') need rewriting to describe mode-routed structure ('Used by /hv-ship Docs Mode and /hv-map'); (3) `references/README.md` Cited-by columns need a consumer-set refresh via grep; (4) `.claude-plugin/plugin.json` skill list drops the standalone entry. The fold isn't done until all four layers move together. <!-- 2026-05-16 -->
