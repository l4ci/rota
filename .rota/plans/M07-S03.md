# M07-S03 — Item lifecycle: notes, close reasons, claim lock, labels, PR/MR

## Goal

In issue mode an item can be claimed, worked, proven, documented (design / plan / Q&A as comments), PR'd with `Closes #N`, and closed or reopened with the right reason, and a fresh session can resume from the issue alone.

## Approach

All tracker mechanics sit in the adapters (comments CRUD, close/reopen with reason, label add/remove, assign) and in `IssueBackend`; helpers stay thin and backend-neutral where a file equivalent exists. Marker comments carry durable per-item artifacts: `<!-- hv:<kind> -->` (proof, design, plan) edited in place, split into `<!-- hv:<kind> i/n -->` parts above 60,000 chars. Append-only context goes through `hv-item-comment` (`<!-- rota:comment <kind> -->`). Label state machine: one of `in-progress` / `needs-review` / `changes-requested` at a time, cleared on close.

Decisions (auto, per the user's continue-automatically instruction, 2026-10-01):
- **Claim lock = label + claim comment.** All hv agents share one gh account, so assignee can't tell workers apart. `hv-item-claim <ref> --as <claim-id>` adds `in-progress`, assigns @me, posts `<!-- rota:claim <claim-id> -->`, re-reads comments: the earliest claim not followed by its `<!-- rota:release <id> -->` wins; a loser releases and exits 3. `hv-item-release` posts the release marker and drops `in-progress`.
- **Readiness check on claim:** `hv-item-ready <ref>` lists missing parts (no acceptance criteria — a heading or checkbox list in the body — and no design/plan note); `/hv-work` warns interactively and refuses under loop autonomy.
- **Close reasons:** done → closed completed + "Done in `<hash>`" comment; dropped / handed-off → GitHub `not planned`, GitLab close + `not-planned` label, comment with reason and note; **blocked → stays open**, label `blocked` (new key `issues.labels.blocked`), comment with the note. `hv-uncomplete` reopens and removes not-planned / blocked.
- **Work flow in issue mode:** `work.mergeStrategy` is treated as `pr`; `/hv-work` claims, opens the PR/MR with `Closes #N` per item, then swaps to `needs-review`. Merging belongs to `/hv-review --queue` (S04).
