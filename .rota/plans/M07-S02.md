# M07-S02 — GitHub + GitLab adapters, capture and read verbs, fake tracker harness

## Goal

With `backlog.backend: "issues"`, capture creates GitHub/GitLab issues and every backlog read (`hv-backlog`, `hv-todo-field`, `hv-summary`, `hv-todo-by-milestone`, `hv-find-milestone-for-items`, `hv-uncertain`) answers from the tracker; lifecycle verbs stay refused until S03.

## Approach

**ID = type letter + issue number** (issue #42 labelled `type:feature` is `F42`; `#42` and `F42` both resolve). The existing `[BFT]\d+` grammar, commit tags and skill prose keep working. **Read path = rendering:** `IssueBackend.backlog_markdown()` renders open issues (and recently closed ones as Done lines, hash slot = `#N`) into BACKLOG.md-shaped text — `FileBackend.backlog_markdown()` returns the file verbatim — so readers keep their parsers and only swap the source. Fields that BACKLOG carries inline (Related, Repos, Subsystem, Captured) live in a trailing `<!-- rota:fields ... -->` block in the issue body; Milestone maps to the native milestone whose title starts with the hv ID (`M07 — …`). **Write path = verbs:** new `hv-item-create` serves both backends (file: next-id + append + optional detail file, byte-identical to today's two-call flow; issues: create issue with type/priority labels). `bin/hvlib_tracker.py` holds `GitHubAdapter` / `GitLabAdapter` with one normalized dict shape, all calls via `hv-tracker-call`. A stateful fake gh/glab (`test/fakes/`) backs every issue-mode test.

## Assumptions

- Native milestone titles start with the hv milestone ID (`M07 — …`); S05 creates them.
- Closed issues render as Done lines with hash slot `#N` and date = closedAt; only the most recent `closed_limit` are rendered.
- Fields block format: `<!-- rota:fields -->` HTML comment at the end of the body, one `Name: value` per line, invisible in the tracker UI.
- Detail file content becomes the issue body in issue mode; there is no `.hv/<kind>/<ID>.md` for issue items.
