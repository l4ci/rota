# M07-S05 — Native milestones, tracking issues, vision and release in issue mode

## Goal

In issue mode, `/hv-vision` creates and manages native milestones with a tracking issue each, slice plans live on that tracking issue, and `/hv-release` gates on, builds notes from, and closes out a milestone.

## Approach

Same move as the backlog: the vision helpers keep their CLIs and JSON shapes and gain an issue-mode source. A milestone is a native milestone titled `MNN — <title>` (description = one-line summary) plus one tracking issue labelled `milestone-tracker` and `status:<planned|active|shipped|archived>`, whose body is the milestone plan (the content of `.hv/milestones/MNN.md` today, frontmatter included) and whose hidden fields block carries `Depends:`. Slice plans are `plan:SNN` notes on the tracking issue. The vision paragraph and the generated `## Active milestones` list stay in `.hv/MILESTONES.md`, like KNOWLEDGE: repo prose, versioned.

Decisions (auto, per the user's continue-automatically instruction):
- **Milestone IDs in issue mode** come from the tracker: next `MNN` = 1 + the highest `M\d+` prefix across all native milestones (open and closed). `hv-next-id milestones` keeps refusing in issue mode; `hv-vision-add` computes the ID through the backend.
- **Status:** `status:` label on the tracking issue; shipped/archived close the native milestone and the tracking issue (shipped → completed, archived → not planned); planned/active reopen both.
- **Release milestone:** `/hv-release` takes `--milestone MNN`; when omitted it uses the single active milestone, asks when several are active, and under loop autonomy stops if it can't pick exactly one.
- **Release notes:** issue mode builds the notes from issues closed as completed in the milestone (Features → New, Bugs → Fixed, Tasks → Changed, each line `Title (#N)`), with commit subjects that reference no item appended under Other.
- **Gate:** block while any issue in the milestone carries `in-progress` / `needs-review` / `changes-requested`; other open issues are listed as a warning (they move to the next milestone or stay open).
- **Close-out (after tag + push, behind the existing manual gates):** close the native milestone, label every closed-completed issue in it `released` with a `Released in vX.Y.Z` comment, set the milestone status to shipped.
