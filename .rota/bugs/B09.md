## Summary

Two defects in the v3→v4 upgrade path that affect **all projects** (not just umbrella), plus a related umbrella gap. Surfaced while upgrading a real project from 3.4.0 → 4.1.0.

## Defect 1 — `hv-init` upgrade-refresh never strips orphaned v3 managed blocks (all projects)

On a v3→v4 upgrade, `/hv-init` refreshes helpers and regenerates the v4 managed blocks, but the v3-only `<!-- rota-context-start -->…<!-- rota-context-end -->` block has **no v4 regenerator**, and `hv-init` does not remove it. Every upgraded project is left with a dangling, misleading block in `CLAUDE.md`:

```
<!-- rota-context-start -->
## Project Context
Domain terminology lives in `.hv/CONTEXT.md`. ...
- _(no terms yet — run `/hv-context` to capture domain terminology)_
<!-- rota-context-end -->
```

It points at the cut `/hv-context` command and the deprecated `.hv/CONTEXT.md`, while the v4 glossary actually lives in the knowledge block. The intended cleanup is `/hv-migrate v4` — but that's exactly the command that can't run on umbrella projects (Defect 3 / F21), and even on single-repo projects it mishandles this block (Defect 2c).

**Expected:** `hv-init` (or `hv-migrate`) strips managed blocks that have no v4 regenerator during the upgrade refresh.

## Defect 2 — `hv-migrate v4` codemod is a blind line-regex; corrupts mentions and helper substrings (all projects)

`bin/hv-migrate`'s `rewrite_text()` does `for line in text.splitlines(): pattern.search(line)` then a blind `pattern.sub()`, with **no mention-vs-usage discrimination and no managed-block awareness**:

- **2a — self-documenting text gets rewritten into nonsense.** Any tracked file that legitimately *names* a cut command — a `BACKLOG.md` entry describing the migration itself, a `KNOWLEDGE.md`/`DECISIONS.md` record of the v3→v4 change — is silently rewritten. In my run, the codemod's dry-run flagged 6 "auto" rewrites that were **100% false positives**: all were a single backlog entry documenting the cut command names. Applying it would have corrupted the very record tracking the migration.
- **2b — substring false-match on a live v4 helper.** `re.compile(r"/hv-map\b")` matches inside `.hv/bin/hv-map-query` (a current v4 helper path), because `\b` sits between `p` and `-`. The codemod flags/rewrites a valid v4 reference.
- **2c — wrong fix even when it "matches".** For the orphaned context block, the codemod rewrites one word (`/hv-context` → `/hv-learn --term`) producing a *still-wrong* artifact (`## Project Context / Domain terminology lives in .hv/CONTEXT.md … run /hv-learn --term`). The correct action is deleting the whole orphan block (Defect 1), which the codemod has no concept of.

**Expected:** skip fenced/inline-code spans and known helper-path tokens; treat managed blocks structurally rather than by line-regex; or at minimum require per-hit confirmation rather than blind `sub()`.

## Defect 3 / context — umbrella projects have no migration path

`hv-migrate v4` refuses umbrella projects (`refusing: not inside a git repo` for non-git umbrellas, plus the explicit F21 deferral). Combined with Defect 1, umbrella users upgrading v3→v4 are left with orphaned blocks and **no supported cleanup** until F21. Tracked already as F21 — noting here only because Defects 1+2 are what make the F21 gap actually bite.

## Repro

1. v3 project with a `<!-- hv-context-* -->` block in `CLAUDE.md` and a backlog/knowledge entry that mentions any cut command name.
2. Upgrade plugin to 4.1.0, run `/hv-init` (helpers refresh; orphan block remains — Defect 1).
3. `/hv-migrate v4` (dry-run): observe false-positive "auto" rewrites on the self-documenting entry (2a) and on `hv-map-query` (2b).

## Workaround used

Hand-swept using the codemod's own `REWRITE_RULES` table + scan scope, but applied **intent-aware**: every regex hit in tracked content was a false positive except the orphaned `hv-context` block, which was removed wholesale; the term-less `.hv/CONTEXT.md` was retired. Net real change for a "full migration" was one block deletion — the blind codemod would have made it net-negative.

## Environment

- hv-skills 3.4.0 → 4.1.0 (Claude Code plugin)
- Project: non-git umbrella with 10 registered sub-repos
