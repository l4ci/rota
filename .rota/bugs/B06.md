# [B06] [P2] hv-todo-drift false-positives on reused IDs across machine syncs

## Symptom

When IDs get reused after old items ship (e.g. machine A ships `[F12]`, machine B mints a new `[F12]` later for a different feature), the detector walks the full `git log` and flags every old commit as drift on the new item.

Observed on 2026-05-16: `F12`, `F13`, `F17`, `F18`, `F19`, `F20`, `F21`, `F22` all flagged as drift on this machine because identically-numbered older features had already shipped — the new items at those IDs are unrelated to those past commits.

## Root cause

`bin/hv-todo-drift` walks the entire `git log` per repo and matches any commit whose subject mentions `[F##]` / `[B##]` / `[T##]`. It has no temporal anchor — the detector cannot distinguish a commit that closed the *current* item from a commit that referenced an older, unrelated item with the same ID.

`.hv/BACKLOG.md` is gitignored, so when work happens on a second machine the local counter mints fresh IDs that may collide with already-shipped IDs from the other machine.

## Fix

Anchor each open item to a capture-time commit hash.

1. **`bin/hv-capture`** writes `Since: <short-hash>` (HEAD at capture time) into each new bullet — fits the existing optional-field syntax used by `Related:` / `Milestone:` / `Subsystem:`.
2. **`bin/hv-todo-drift`** parses `Since:` per open ID; when present, runs `git log <since>..HEAD` for that ID instead of full log. When absent, falls back to current full-log behavior (backwards-compatible for existing items without anchors).
3. **Backfill**: a `--backfill-since` flag (on `hv-capture` or a sibling one-shot helper) stamps `Since: HEAD` on every currently-open item lacking the field. Needed to silence the 8 active false-positives without re-capturing each item.
4. **Smoke test** in `test/sections/`: capture an item; ship a commit referencing its ID; verify drift fires. Then capture a *new* item using the same ID shape and verify the older commit does **not** drift-trigger the new item.

## Out of scope

- Cross-machine BACKLOG.md sync (option 3 from the original triage) — deferred.
- Per-device fingerprint prefixes on IDs (option 0) — rejected as overkill.
