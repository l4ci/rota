# B08 — `/hv-migrate v4 --apply` never bumps the recorded version stamp

## Symptom

After a successful `/hv-migrate v4 --apply` run that rewrites 48 references across 7 files, the project's recorded hv-skills version is unchanged:

```
$ /hv-migrate v4 --apply
applied. backup at: .hv/migrate-backup/20260517T124810
$ python3 -c "import json; c=json.load(open('.hv/config.json')); print(c.get('hvSkills',{}).get('version'))"
3.3.0
$ .hv/bin/hv-preflight
hv-skills drift: project at 3.3.0, plugin at 4.1.0 — run /hv-init to refresh helpers
```

The preflight nudge keeps firing forever — there's no command path that bumps the stamp.

## Root cause

`.hv/bin/hv-migrate` apply block (lines 416–433):

```python
# APPLY path — back up first, then write.
ts = dt.datetime.now().strftime("%Y%m%dT%H%M%S")
backup_root = Path(".hv/migrate-backup") / ts
backup_root.mkdir(parents=True, exist_ok=True)

for r in rewrites:
    backup_dest = backup_root / r["path"]
    backup_dest.parent.mkdir(parents=True, exist_ok=True)
    shutil.copy2(r["path"], backup_dest)
    write_text_atomic(r["path"], r["new"])

if ctx_plan["action"] != "none":
    apply_context_migration(ctx_plan, backup_root)

if bin_plan:
    apply_removed_binaries(bin_plan, backup_root)

print(f"applied. backup at: {backup_root}")
```

Nothing writes back the new hv-skills version. The `noop` branch (line 408) is plan-based — re-running after a successful apply hits *"noop: project is already on v4 (no rewrites, no CONTEXT.md, no stale bins)"* because the codemod has nothing left to do, not because the version was bumped. Functional idempotency holds, but the recorded-state question stays open.

## Reproduction

```bash
# Any v3.x project after a successful /hv-migrate v4 --apply.
/hv-migrate v4 --apply                              # exits 0
.hv/bin/hv-preflight                                # still nags about drift
python3 -c "import json; print(json.load(open('.hv/config.json'))['hvSkills']['version'])"
# → still the pre-migration value
```

## Suggested fix

At the end of the apply block, write the current plugin version into both keys (top-level for legacy compatibility and `hvSkills.version` for the canonical shape):

```python
# After all rewrites land, stamp the new version so preflight stops nagging.
import subprocess
plugin_version = read_plugin_version()  # from plugin.json next to bin/
subprocess.run([".hv/bin/hv-config-set", "hvSkills.version", plugin_version], check=True)
# Drop the legacy top-level mirror if present (left over from the B07 workaround).
```

Bumping the stamp converts a successful apply into a permanently-recognized v4 state — and lets `hv-preflight` go silent without manual intervention.
