## What happened
`/hv-learn` Step 8 auto-split (steps 3–7) is silent on the tier sidecar — it specifies only KNOWLEDGE.md heading/bullet moves + `hv-knowledge-index`, but renaming a `## Topic` heading orphans every titled bullet's `.hv/knowledge-tier.json` entry, which is keyed `"<topic>::<title>"`. No rename/topic helper exists (only `hv-knowledge-merge`/`amend`/`tier`/`migrate`). Under `autonomy.level: loop|auto` the split runs unattended → silent loss of tier (promotion state) and hit counts for every titled bullet under a split topic. Found 2026-05-16 splitting 3 oversize Architecture topics into 7 facets: had to hand-re-key the sidecar (`Architecture: Server, schema & MCP runtime::<title>` → `Architecture: MCP runtime & wire contracts::<title>`) because nothing does it.

## Expected
Step 8 auto-split should re-key `knowledge-tier.json` as part of the heading move (preferably via a new atomic `hv-knowledge-rename-topic` helper that moves headings + re-keys the sidecar in one step), so tier/hit state survives a topic split — especially under unattended `loop`/`auto` autonomy.
