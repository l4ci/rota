# T115: Proof separate from acceptance

> Related TODO entry: `[T115]` in `.hv/BACKLOG.md`

## Summary

Verification evidence gets recorded per item in a `## Proof` section of the detail file via a new `hv-proof-add` helper; review and QA read it instead of re-deriving; completion refuses items with no proof unless overridden. Adopted from openrig's "progress is derived from evidence" rule.

## Detail

### Helper

```
hv-proof-add <ID> --check <name> --result PASS|FAIL --evidence <path-or-text> [--sha <commit>]
```

- Creates `.hv/<kind>/<ID>.md` if missing (minimal detail-file shape), appends a row to `## Proof`:
  `- <date> · <check> · <PASS|FAIL> · <sha> · <evidence>`
- Idempotent on identical row; exit 0. Writes through `hvlib_io.update` with the sibling lock.
- `hv-proof-show <ID>` (or `hv-artifact-show` extension) prints the section.

### Consumers

- `/hv-work` Step 7 (both backends): each verified task appends one row (verify command, result, commit sha). Under tmux/herdr, `hv-worker-gate` appends the re-verify row.
- `/hv-review` Stage 1 brief gets the proof rows as `**Recorded proof:**` and is told not to re-run what is already proven; it may spot-check one.
- `/hv-qa run` writes its executable-check results as proof rows for every item on the branch.
- `hv-complete <ID>` exits 3 with "no proof recorded, pass --no-proof to override" when the section is empty. Loop mode never auto-passes `--no-proof`.

### Separation rule (from openrig)

Attaching proof ≠ accepting the item ≠ judging the milestone. Proof rows are facts; acceptance is `/hv-review` PASS or the user; hv-complete is the acceptance write, and it must find proof first.

### Smoke

Section covering: add/show, idempotency, hv-complete refusal and override, byte-identical BACKLOG output when proof exists.
