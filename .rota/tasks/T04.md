## What happened
When a multi-task plan has two T# steps that touch the same file and `work.isolation` is `branch`, the parallel-dispatch guard forces them to serialize unless the orchestrator merges one task's edit into the other at dispatch time. On M02-S02, T4's `_build_employee_view` server.py addition was absorbed into T3 so T4 only touched template + CSS — both could then run as write-only workers in parallel. Plan files written by `/hv-plan` can't anticipate this; the orchestrator decides at execution time.

## Expected
Either `/hv-plan` should detect file-collision pairs in a multi-task plan and either merge them or assign them to separate waves, OR `/hv-work` should explicitly document the absorption pattern as the orchestrator-side recourse so the technique is reproducible across runs without per-orchestrator improvisation.
