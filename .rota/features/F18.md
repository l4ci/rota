# F18 — Fold /hv-context into /hv-learn --term

## Why

`/hv-context` writes domain terminology to `.hv/CONTEXT.md`; `/hv-learn` writes durable observations to `.hv/KNOWLEDGE.md`. The two surfaces overlap conceptually — both are "remember this about the project" — and forcing users to pick the right one is friction. v4.0 folds context into learn under a `--term` flag, but the data migration is the snag and the reason this is the highest-risk cut in M01.

## Two viable migration models

`/hv-brainstorm` should pick between these before `/hv-plan`:

**Option A — Glossary topic in KNOWLEDGE.md.** Add a top-level `## Glossary` topic to KNOWLEDGE.md. Each term becomes an entry under that topic. `/hv-learn --term <name>` writes there; `hv-knowledge-query` returns matches whenever a query overlaps a glossary entry. CONTEXT.md migrated by copying each term as a child of `## Glossary`. Simpler for users — one section, easy to scan. Risk: inflates KNOWLEDGE.md, blurs the "observations vs definitions" distinction.

**Option B — `kind: term` frontmatter on learning entries.** Existing `.hv/learnings/*.md` already use frontmatter. Terms become learnings with `kind: term` set. `/hv-learn --term` sets the kind; queries can filter on it. CONTEXT.md migrated entry-by-entry to `.hv/learnings/<term>.md` with `kind: term`. Cleaner technically. Risk: the distinction lives in frontmatter the user rarely sees.

## What `/hv-migrate v4` does for existing projects

For each project's `.hv/CONTEXT.md`:

1. Parse the term entries
2. Write them into KNOWLEDGE.md under the chosen model
3. Move CONTEXT.md to `.hv/migrate-backup/<timestamp>/CONTEXT.md`
4. Update CLAUDE.md managed-block to drop the "Project Context" section (replace with the glossary topic link, or remove entirely if Option B)

Same shape as all other migrate ops: `--dry-run` default, `--apply` to write, atomic per-project.

## Acceptance for this feature

- `/hv-context` skill removed (folder, plugin.json, marketplace.json)
- `/hv-learn --term <name>` flag accepted; writes per chosen model
- `hv-context-add` helper either removed or aliased to the learn-side helper
- `hv-context-query` helper either removed or re-routed under the hood
- `/hv-migrate v4` handles existing CONTEXT.md projects (the migration logic is part of THIS feature, but the migrate skill itself is a separate Major feature in M01 — captured later)
- All surviving SKILL.md cross-refs to `/hv-context` rewritten

## Open questions

- Option A vs B — `/hv-brainstorm` decides
- Projects where the user has hand-curated CONTEXT.md with non-glossary content (tables, ASCII diagrams, paragraphs): migrate-bail with an instruction to manual-port? Or best-effort?
- Is the CLAUDE.md managed-block update a separate skill change, or part of this fold?
- For Option A: how does `hv-knowledge-query` differentiate glossary hits from observation hits in its output, if at all?
