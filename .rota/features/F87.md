Round 1 (2026-10-04) took ~15 orchestrator calls before the first assignment:
- `round start` defaults to scope `milestone`; with no active milestone `candidates` is empty, and `--scope next` is empty too. Only `--scope slate --items` worked.
- The readiness check needs criteria in the detail file or a design/plan note. `plan add` needs a milestone key (M01-B07), so `design add/put` was the only route.
- Workers branch from the base, so every `.rota/` bookkeeping change (capture, design) needed its own PR before assign.

## Options to weigh
- Scope fallback: with no active milestone, `start` offers open backlog items (or says why the list is empty and which flag to use).
- Readiness: accept criteria passed in `assign --body-file`, or allow item-keyed plans without a milestone.
- Bookkeeping: let assign carry the orchestrator's uncommitted `.rota/` notes into the brief, or batch them into one commit.

## Acceptance
- [ ] A fresh repo with open backlog items and no milestone reaches a first `assign` in at most start + assign
- [ ] Empty candidates always come with a reason and the next command
