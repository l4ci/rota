# F81: herdr dispatch backend `work.dispatch: "herdr"`

> Related TODO entry: `[F81]` in `.hv/BACKLOG.md`

## Summary

Second worker backend beside tmux ([F78]): each slot is a herdr tab in the current workspace, running Claude Code in an hv-managed worktree. Host primitives are extracted into sourced libs so `hv-worker-dispatch`, `hv-worker-poll` and `hv-worker-session` pick tmux or herdr by config; pool, gate and accounts stay untouched.

## Detail

### Decisions (user, 2026-09-30)

- Slots use hv-managed worktrees (`.claude/worktrees/hv-worker/wN`) adopted via `herdr tab create --cwd`, not `herdr worktree create`. Keeps `hv-worker-pool`, `hv-worker-gate`, `hv-worker-account` unchanged.
- Order: after [F80].

### Host primitive libs

`bin/hv-host-tmux.sh` (absorbs `hv-tmux-send.sh` plus new-window / kill-window / capture-pane / `$TMUX` check) and `bin/hv-host-herdr.sh`. Both define-only (`*.sh` convention), same function names:

| Primitive | tmux | herdr |
|---|---|---|
| `hv_host_in_session` | `[ -n "$TMUX" ]` | `[ "$HERDR_ENV" = 1 ]` |
| `hv_host_spawn <slot> <cwd> [env...]` | `tmux new-window -n` + launch cmd | `herdr tab create --workspace $HERDR_WORKSPACE_ID --cwd <wt> --env CLAUDE_CONFIG_DIR=<dir> --label <slot> --no-focus` → pane id; then `herdr agent start <slot> --kind claude --pane <id> -- --model <m> --dangerously-skip-permissions`; on `agent_not_ready` (folder-trust prompt, default "No, exit") send `agent send-keys <slot> down enter`, then `agent wait --until idle` |
| `hv_host_send <slot> <file>` | paste-buffer + Enter + re-capture (existing) | `herdr agent prompt <slot> "$(cat file)" --wait --timeout 60000`; `agent_blocked` → return 5 (dialog up), `agent_prompt_stalled` → return 4 |
| `hv_host_capture <slot> <lines>` | `tmux capture-pane -pJ` | `herdr agent read <slot> --source recent-unwrapped --lines N` |
| `hv_host_status <slot>` | (none; classifier only) | `herdr agent get <slot>` → `agent_status` |
| `hv_host_wait <slot> <until> <timeout>` | poll loop | `herdr agent wait <slot> --until <states> --timeout` |
| `hv_host_kill <slot>` | `tmux kill-window` | `herdr agent prompt <slot> "/exit"` (no wait) + `herdr tab close` |
| `hv_host_notify <title> <body>` | no-op | `herdr notification show --sound request` |

Selection: `work.dispatch` read once in `hv-preamble.sh`-adjacent helper (`hv-host-select.sh`) that sources the matching lib; `subagent` sources nothing.

### Poll mapping

`hv-worker-poll` under herdr: read native status first, then reuse the existing `classify()` text block on the captured pane.

| herdr `agent_status` | hv state |
|---|---|
| working | BUSY |
| blocked | NEEDS-PERMISSION, unless pane shows `HV-BLOCKED` sentinel → BLOCKED |
| idle / done | sentinel scan: `HV-DONE` → DONE, `HV-BLOCKED` → BLOCKED, usage-limit phrases → LIMITED, else IDLE |
| unknown | DEAD check via existing `API Error` / `Resume this session` regexes; otherwise UNKNOWN (new state, surfaced, never treated as done) |

`--settle` double-capture still applies to `idle`/`unknown` for the `DEAD` rule. On BLOCKED / NEEDS-PERMISSION call `hv_host_notify`.

### Pool and gate changes

- `.hv/workers.json` slot field `window` → backend-neutral `handle` (`session:wN` for tmux, `w1:t7` tab id for herdr). Migration: `hv-worker-pool init` rewrites `window` to `handle` if present.
- Close the known gap: nothing writes `slot.pr` / `slot.state` / `slot.task`. `hv-worker-dispatch` writes `task`+`state=busy`; `hv-worker-poll` writes `state` and parses the PR URL from `HV-DONE <slot> <pr>` into `pr`, so `hv-worker-gate` uses `gh pr merge` instead of falling back to a local merge. Applies to tmux too.
- Operator handoff (`hv-worker-session ensure`) herdr variant: `herdr tab create` in the current workspace + `herdr agent start operator --kind claude -- --continue --model <orchestrator> --permission-mode auto`, then `agent prompt` with the instruction file. Print an attach block naming the tab.

### Verified facts (2026-09-30)

- herdr 0.9.1 at `~/.local/bin/herdr`, protocol 22, server running; this session runs inside it (`HERDR_ENV=1`). Docs describe 0.9.3 (not diffed).
- API: NDJSON over unix socket `$HERDR_SOCKET_PATH` (`~/.config/herdr/herdr.sock`), no auth, 103 methods, each with a CLI twin printing JSON; errors on stderr as JSON, exit 1. Schema saved during research via `herdr api schema --json`.
- Managed panes get `HERDR_ENV`, `HERDR_SOCKET_PATH`, `HERDR_WORKSPACE_ID`, `HERDR_TAB_ID`, `HERDR_PANE_ID`, `HERDR_BIN_PATH`.
- Agent states: idle, working, blocked, done, unknown. `blocked` = approval/question UI detected. `unknown` ≠ finished. No approve API; workers run with permissions skipped.
- `agent prompt --wait` returns on first settled idle/done/blocked; refuses with `agent_blocked` if a dialog is up; `agent_prompt_stalled` if no state change in 5s (harmless for client-side slash commands like `/exit`).
- `agent start` returns after detection (~3–4s); pane must be at a bare shell prompt; a fresh worktree hits the folder-trust prompt.
- Account selection must go through `--env CLAUDE_CONFIG_DIR` at tab creation (`agent start` ignores shell aliases/wrappers). Install the herdr Claude integration once per config dir.
- `focused=true` on an agent means a human is looking at it: do not prompt or clear it.
- Existing prompt-level runbook: `stray:orchestrate-herdr` skill (worker contract, provenance, merge gate). Not hv helpers.
- Unverified: exact `.result.*` nesting of `tab create` / `agent start` responses (from skill text, not live calls); whether one socket connection carries multiple requests (use one per request).
