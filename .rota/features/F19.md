# F19 — /hv-migrate v4 codemod

## Why

v4.0 hard-cuts 8 commands with no aliases and no stubs (per M01 design — bare "skill not found" is the post-cut UX). The codemod is the only safety net users have. Without it, anyone running v3 → v4 upgrades a project full of stale references in `.hv/BACKLOG.md`, `.hv/plans/*`, `.hv/designs/*`, `.hv/handoffs/*`, and the project's own `CLAUDE.md`. One `/hv-migrate v4` invocation must leave a project's references coherent with the new surface.

## Shape

- New skill at `hv-migrate/SKILL.md`. Versioned arg required: `/hv-migrate v4` (future hard breaks reuse the pattern: `/hv-migrate v5`, etc.).
- `--dry-run` is **default**. Prints a diff per file. No writes.
- `--apply` performs the rewrite.
- Idempotent — re-runnable. Second invocation should be a no-op.
- Atomic backup: every file the codemod touches gets a copy at `.hv/migrate-backup/<ISO-timestamp>/<relative-path>` before rewrite. User can compare or revert.
- Final summary: N files touched, M references rewritten, K files that contained ambiguous references requiring manual review.

## Scan scope

| Path | Action |
|---|---|
| `.hv/BACKLOG.md` | Rewrite old command names in entry bodies |
| `.hv/plans/*.md` | Rewrite old command names in plan prose |
| `.hv/designs/*.md` | Rewrite old command names in design prose |
| `.hv/handoffs/*.md` | Rewrite old command names in handoff notes |
| `.hv/qa/*.md` | Rewrite old command names in QA strategy prose |
| `.hv/CONTEXT.md` | Special-cased — migrate to KNOWLEDGE.md per F18 |
| Project root `CLAUDE.md` | Rewrite old command names in the managed block AND user-authored prose; managed block is regenerated from the live index helper |
| `.hv/MILESTONES.md` and `.hv/milestones/*` | Rewrite old command names in milestone prose |
| `.hv/KNOWLEDGE.md` | Rewrite old command names in learnings prose |
| `.hv/DECISIONS.md` | Rewrite old command names in decision prose |

## Rewrite rules

Eight literal rules; each is a regex match + replacement. Bounded by word boundaries to avoid mangling `/hv-context` mentions inside other contexts.

| From | To |
|---|---|
| `/hv-c\b` (when not part of `/hv-capture`) | `/hv-capture` |
| `/hv-assume\b` | `/hv-work --preview` |
| `/hv-rm\b <ID>` | `/hv-capture --remove <ID>` |
| `/hv-rm\b` (no ID arg) | `/hv-capture --remove` |
| `/hv-undo\b` | `/hv-ship --undo` |
| `/hv-issues\b` | `/hv-capture --from-github` (with a note: caller may need `--from-gitlab` instead — flag for manual review) |
| `/hv-context\b` | `/hv-learn --term` (special-case — also runs the CONTEXT.md → KNOWLEDGE.md data migration from F18) |
| `/hv-map\b` | `/hv-init --map` (first-run case) OR delete the line (post-first-run case — flag for manual review) |
| `/hv-docs\b` | `/hv-ship --docs` |

Ambiguous rewrites (`/hv-issues` → could be github or gitlab; `/hv-map` → could be init or no-op) get flagged with a comment and surface in the final summary's manual-review list, not auto-rewritten.

## Safety

- `--dry-run` is default. `--apply` required to write.
- Backup directory `.hv/migrate-backup/<ISO-timestamp>/` preserves the pre-rewrite tree.
- Refuse to run if the working tree has uncommitted changes outside `.hv/` (user should commit or stash first).
- Refuse to re-run inside an existing backup directory.
- If `.hv/CONTEXT.md` exists, abort with a clear error unless F18's migration logic has been wired in (`hv-context-migrate` helper) — F19 depends on F18 for that path.

## Dogfooding

This codemod runs against THIS repo's `.hv/` during development. If `/hv-migrate v4 --dry-run` doesn't cleanly rewrite hv-skills's own state, it won't work for users. Smoke-test section required.

## Acceptance

- `/hv-migrate` skill folder, plugin.json entry, marketplace.json entry exist.
- `v4` is the only supported version arg at v4.0 GA. Unknown version arg exits with helpful error.
- Eight rewrite rules implemented. Word-boundary safe.
- `--dry-run` default, `--apply` flag works, backup tree created on apply.
- Idempotent: second `--apply` after a clean first run rewrites zero files.
- CONTEXT.md → KNOWLEDGE.md path (consumes F18) works.
- Smoke-test section dogfoods against hv-skills's own state.

## Open questions

- Regex vs AST? Markdown is mostly plain — regex with word boundaries should suffice. Risk: false positives in code blocks. Maybe skip rewrite inside fenced code blocks.
- Should the codemod also update user shell scripts / aliases? Out of scope — repo files only.
- npm/skills marketplace post-install hook to print "run /hv-migrate v4"? Or just rely on README + release notes?
- Telemetry on rewrite counts (anonymized, opt-in) to validate the cuts actually were referenced widely? Probably out of scope for v4.0.
