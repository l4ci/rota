# F01 — Browser-driven QA skill (`/hv-qa`)

## Why

Current verification in `/hv-work` and `/hv-ship` is structural — git diff, greps, re-running a reproducer. That catches "code changed" but not "running app behaves correctly." Behavioral UI regressions, perf cliffs, and a11y violations slip through because nothing exercises the deployed feature against the real DOM.

Inspired by gstack's `/qa <url>` and `/devex-review`, which drive a real browser as a verification sensor.

## Shape

Three sub-modes with distinct evidence sources:

- `/hv-qa --perf <url>` — Lighthouse / CDP traces / Core Web Vitals. Deterministic; thresholds in config.
- `/hv-qa --a11y <url>` — axe-core via Playwright. Rule violations; deterministic.
- `/hv-qa --ux <url>` — screenshot + DOM + console + network captured by Playwright, fed to an LLM-as-judge against an explicit rubric (Nielsen 10, mobile reachability, contrast, target sizes). The novel piece — running-app evaluation that existing code-review skills (`audit`, `polish`, `ui-ux-pro-max`) can't do because they only see source.

Default with no flag: all three modes against the same target.

## Findings → backlog

Each finding routes through `/hv-capture` with severity + evidence + suggested fix. Minimum-severity gate in `.hv/config.json` to prevent UX-mode LLM spam ("consider more whitespace") from drowning TODO.md.

## Open questions

- Auto-capture as `[B]` / `[F]` items, or block `/hv-ship` until acknowledged, or both?
- Where does target URL come from — explicit arg, dev-server detection from `package.json`, or both?
- Headed vs. headless default. Headed gives visible signal during sessions; headless is CI-friendly.
- Cost ceiling for `--ux` mode (LLM calls per finding).

## Implementation notes

- Playwright binary management is heavy — likely a one-time `/hv-qa --setup` that installs browsers, similar to gstack's setup script.
- Hostname-scoped notes (per-site quirks the QA agent learned) could share storage with `/hv-learn` — see gstack domain-skills pattern, also captured as F03's promotion lifecycle.
- Runs cleanly in CI only if headless + auth fixtures land — out of scope for v1.
