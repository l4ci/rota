# F80: Codex verification harness `hv-codex-verify`

> Related TODO entry: `[F80]` in `.hv/BACKLOG.md`

## Summary

New helper `bin/hv-codex-verify` runs Codex headlessly against a worktree with a brief and returns a structured PASS/FAIL/ERROR verdict plus findings JSON. First wire points: `/hv-ship` second opinion via `ship.secondOpinionRunner: codex`, and a documented runner entry for `/hv-qa` strategies. Merge-gate re-verify is a later, separate item.

## Detail

### Decisions (user, 2026-09-30)

- Ships after the host sandbox is fixed ([T113]); until then the helper must still run correctly under `-s danger-full-access` with a diff-guard.
- Scope now: second opinion + QA runner. Later: `hv-worker-gate` re-verify.
- Order: this feature first, then [F81] herdr backend.

### Helper contract

```
hv-codex-verify --worktree <path> --brief <file> [--schema <file>] [--sandbox read-only|workspace-write|danger-full-access] [--timeout <s>] [--doctor]
```

Wraps:

```
cd "$WORKTREE" && codex exec -s <mode> -C "$PWD" --ephemeral --color never \
  --output-schema "$SCHEMA" -o "$OUT/last.json" --json - \
  < "$BRIEF" > "$OUT/events.jsonl" 2> "$OUT/stderr.txt"
```

- Last stdout line: `PASS` / `FAIL` / `ERROR`. Exit 0 / 1 / 2.
- Findings JSON (from `last.json`): `{verdict, summary, findings[{severity, file, line, title, body}], next_steps}`. Schema is `additionalProperties:false` with every property in `required` (same rule the codex plugin's `schemas/review-output.schema.json` follows).
- `ERROR`, never `FAIL`, on any of: non-zero codex exit; `last.json` missing or unparsable; no `turn.completed` event in `events.jsonl`; any `bwrap` text in events or stderr; worktree dirty after the run (`git status --porcelain` captured before and after, must be identical). The dirty-tree guard exists because full-access mode can write.
- Artifacts to `.hv/qa-runs/<ts>/codex/` (gitignored).
- Prompt body composed in XML blocks (`<task>`, `<structured_output_contract>`, `<grounding_rules>`) per the codex plugin's gpt-5-4-prompting skill; grounding rule says "do not modify files, verify by running commands".
- `--doctor`: probes `codex --version`, `codex login status`, and a trivial `codex exec -s read-only` run; prints the bwrap diagnosis and the host fix from [T113] when the sandbox is broken.

### Wire point 1: `/hv-ship` Step 3.5

Existing `references/review-verdict-routing.md` routing stays unchanged.

### Verified facts (2026-09-30)

- codex-cli 0.159.2, ChatGPT login, plugin openai-codex/codex 1.0.6 (uses `codex app-server` JSON-RPC, not `codex exec`).
- `codex exec --output-schema` returned a schema-valid final message in ~26s on a throwaway repo; ~50–80k input tokens, mostly cached.
- Native `codex review` is prose-only, exit 0 means finished not passed; not usable as a gate.
- Codex reads `AGENTS.md` (git root down to cwd), not `CLAUDE.md`. A worktree is its own root.
- `--ephemeral` avoids session files; `--ignore-user-config` makes runs reproducible.
- Plugin's stop-time review gate is per-turn (ALLOW/BLOCK first line), not branch-level; not reusable for ship.
