# F21 — Umbrella-aware KNOWLEDGE.md

## Why

CONTEXT.md currently supports umbrella mode — per-sub-repo `.hv/contexts/<name>/CONTEXT.md` files plus `CONTEXT-MAP.md` for cross-repo visibility. F18 folds /hv-context into /hv-learn --term and merges term data into KNOWLEDGE.md, but KNOWLEDGE.md has no umbrella support today. Umbrella users running /hv-migrate v4 will be blocked by an explicit error until KNOWLEDGE.md gains parallel umbrella support. This feature closes that gap.

Split from F18 because:
- F18 is a data-shape fold (one storage model → another). Bounded.
- F21 is new infrastructure (single-file → per-sub-repo files). Distinct work.
- Sharing a feature creates a "fold OR umbrella slips, M01 slips" risk.

## Shape

- Per-sub-repo storage: `.hv/knowledge/<repo-name>/KNOWLEDGE.md` for each registered sub-repo; umbrella-shared `.hv/KNOWLEDGE.md` for cross-repo learnings.
- Helper rewiring: `hv-knowledge-merge`, `hv-knowledge-query`, `hv-knowledge-index`, `hv-knowledge-tier`, `hv-knowledge-amend` all gain umbrella-aware target resolution (mirrors `hv-context-add` --repo dispatch).
- Tier sidecar: `.hv/knowledge-tier.json` either splits per-sub-repo or stays single (decided in F21 brainstorm).
- CLAUDE.md managed-block: shared (one block per umbrella parent) or per-sub-repo (separate blocks). Decided in F21 brainstorm.
- /hv-learn skill: --repo flag added; without it, resolves active sub-repo via hv-resolve-repo (same pattern as hv-context-add today).
- /hv-migrate v4 umbrella branch: when F21 ships, /hv-migrate v4 stops erroring on umbrella projects and instead writes terms into the right per-sub-repo KNOWLEDGE.md files.

## Acceptance

- Per-sub-repo .hv/knowledge/<name>/KNOWLEDGE.md works for /hv-learn writes.
- All five hv-knowledge-* helpers handle umbrella scope correctly (target-file resolution, alias-uniqueness scope, query merging across repos with `> from:` prefix).
- Tier sidecar decision made and implemented.
- CLAUDE.md managed-block decision made and implemented.
- /hv-migrate v4 umbrella branch tested against a synthetic umbrella project with terms in multiple sub-repos.
- Smoke-test section covers umbrella write/read/query/migrate paths.

## Open questions

- Tier sidecar: per-sub-repo or single? (Affects whether a learning's tier in one repo affects the same-titled learning in another.)
- CLAUDE.md managed-block: one shared block at umbrella parent, or per-sub-repo blocks? (Affects which /hv-work runs consult which KNOWLEDGE.md.)
- Alias uniqueness scope: per-sub-repo (collisions OK across sub-repos) or global (no collisions anywhere)? Mirrors the CONTEXT-MAP.md design.
- Cross-repo Glossary queries: does /hv-knowledge-query Glossary list terms from all sub-repos or just the active one?
- Ship in v4.0 alongside F18, or defer to v4.1? (Affects whether umbrella users wait one release or zero.)
