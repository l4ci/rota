# F83: Codex multi-account worker slots

> Related TODO entry: `[F83]` in `.hv/BACKLOG.md`

## Summary

Mirror F79 for Codex: map slots to their own `CODEX_HOME` so each authenticates as a separate account, and allow a Codex `workerCommand`. Usage balancing needs a Codex-side meter; until one exists, Codex slots fall back to rotation.

## Detail

**herdr already launches Codex natively** (checked against herdr 0.9.3): `herdr agent start --kind codex --pane <id>` is supported, next to `claude` and about 20 other agent kinds. The herdr side mostly means:

- Dropping the claude-only refusal in `bin/hv-host-herdr.sh:128` and deriving `--kind` from the worker command instead of hardcoding `--kind claude` (`bin/hv-host-herdr.sh:153`).
- Passing `--env CODEX_HOME=<dir>` at `herdr tab create`, the same way `CLAUDE_CONFIG_DIR` is passed today (`bin/hv-host-herdr.sh:140`). The account has to be set at tab creation because `agent start` runs inside the tab's shell.
- Checking that herdr's state classifier (`idle`/`working`/`blocked`/`done`) and hv's startup-dialog handling cover Codex's TUI, since both were built and tested against Claude.

**Still open:**
- The tmux host launches the command directly. Check how `hv-host-tmux.sh` prefixes the account env and whether its pane classifier understands Codex output.
- `hv-worker-account` only reads Anthropic's OAuth usage endpoint. Codex slots need their own meter source or a rotation-only policy.
- The worker contract and the `HV-BLOCKED` escalation marker assume Claude Code's behavior. Verify that Codex follows them.
