# [F06] Skill-format CI validator (GitHub Actions)

Add a GitHub Actions workflow that statically validates every `hv-*/SKILL.md` on PRs and pushes. Codifies `references/authoring-conventions.md` so authoring drift is caught at PR time rather than smoke-suite or install time. Borrowed pattern from claude-spellbook's CI "Validate Skill Format" job. Complements `test/smoke.sh` (integration-only, slow, sequential) with a fast static-schema check.

## Checks the workflow should perform

- **Frontmatter present and valid.** Every `hv-*/SKILL.md` has a frontmatter block with non-empty `name` and `description` fields.
- **Banner block present.** First non-frontmatter content matches the banner format from `references/banner-preamble.md` (codeblock with `─` characters, skill emoji + title line, triggers + pairs line).
- **References resolve.** Every `references/*.md` link in any SKILL.md points to a file that exists in this repo (no broken relative refs).
- **Version consistency.** `.claude-plugin/plugin.json` `version` matches the topmost version heading in `CHANGELOG.md`. Catches release/version drift like the v2.3.1/v3.1.0 plugin-cache mismatch surfaced in May 2026.
- **Authoring-conventions sanity.** Optional grep-based checks for rule violations in `references/authoring-conventions.md` that are mechanically detectable (e.g., new SKILL.md files that don't print a banner; feature-flag defaults in code-paths that should be `false`).

## Suggested layout

- `.github/workflows/skill-format.yml` — runs on `pull_request` and `push` to `main`.
- `test/validate-skills.py` — Python script invoked by the workflow. Exits 0 on pass, non-zero with per-file diagnostics on fail.

## Open questions

- Should the validator also lint `references/*.md` themselves for orphans (referenced by nothing)?
- Do we want a `--fix` mode for trivially fixable issues (missing trailing newline, banner-codeblock language hint)?
- Should it gate `/hv-release` locally too, or stay CI-only? CI-only is cleaner; local enforcement risks blocking work for cosmetic issues mid-flow.

## Source signal

claude-spellbook (https://github.com/kid-sid/claude-spellbook) ships a CI matrix that validates skill frontmatter, required sections, and a checklist item. Our authoring surface is richer (banner block, references graph, version stamping) but the same pattern fits.
